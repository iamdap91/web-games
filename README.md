# Web Games

메이플스토리 월드 리소스를 활용하는 로컬 전용 웹 캔버스 미니게임 프로젝트.
전체 MMORPG를 재현하기보다, 소수의 조작과 규칙으로 완성되는 작은 게임을 만든다.

코드, 커밋, 디렉토리 구성 및 검증 기준은 [AGENTS.md](AGENTS.md)에 정리한다.

## 현재 게임: C-2 연구소

8번 출구 방식의 횡스크롤 세미공포 프로토타입. 알카드노 연구소 C-2를 하나의 단층 통로로 재구성한다.

- 모험가 한 명의 좌우 이동·점프·플래시점프만 사용한다. NPC·전투·소리·수직 발판은 없다. 침입자는 문에서 양쪽으로 손을 뻗는 이상현상으로만 등장한다.
- 0번 방은 정상 풍경이다. 이상이 있으면 왼쪽 끝으로 되돌아가고 없으면 오른쪽 끝으로 나간다. 시작 문 옆 안내판에서 이 규칙을 읽는다.
- 시작 문 위 표시가 현재 방 번호다. 올바른 출구를 고르면 0부터 8까지 올라가며, 첫 정상 방도 포함해 8회 연속 성공하면 따뜻한 색감의 8번 방에 도착한다. 여기에서도 직접 이동·점프할 수 있으며, 오른쪽으로 나아가 캐릭터와 잔상이 모두 빛에 가려지면 탈출한다. 오답은 숫자에 잠깐 노이즈가 생긴 뒤 0번 방으로 돌아간다. 별도 결과 팝업 없이 암전·입장 연출로 다음 방에 연결한다.
- 정상과 이상현상 15종이 있다. 일반 진행의 1~7번 방은 이상현상 70%·정상 30%로 독립 추첨한다. 이상 중 ‘텅 빈 중앙’은 1/35, 나머지 14종은 남은 확률을 균등하게 나눈다. 0번 방은 정상이며, 8번 방은 출구다.
- 배관은 접근 시 한 번 발동한다. 마지막 배관 근처(x=1720)에서 5번 → 2번 → 1번이 각각 0초·0.56초·0.78초에 낙하하며 3·4번은 그대로 남는다. 각 배관이 바닥에 닿을 때 짧은 흔들림이 발생한다. 뒤로 물러나도 연쇄 낙하는 이어지며 내려온 상태로 남는다. 정상 방에도 동일한 배관이 천장에 있어 개수만으로 이상 여부를 알 수 없다. 낙하 중 몸에 맞으면 짧은 충격 연출 뒤 0번 방으로 복귀하고 번호에 노이즈가 발생한다. 낙하가 끝난 배관은 통과할 수 있다. 발동 위치와 시간은 고정이며 빠른 이동도 판정한다.
- 세밀한 차이 찾기보다 큰 형태 변화와 움직임을 우선한다. 부재형 이상은 앞으로 추가하더라도 드물게 사용한다.

‘공간 절단’은 x=1280에서 시작된다. 모바일 대응을 위해 절단 진행 속도를 최초 구현의 68%로 낮췄다(20% 감속 후 추가 15% 감속). 약 0.618초 절단선 예고 후 칼날이 내려오며, 오른쪽부터 약 0.912초 간격으로 여섯 구역을 잘라 떨어뜨린다. 왼쪽 입구(x=235)에 닿으면 탈출하고, 잘린 구역에 남거나 출구가 잘리면 조각과 함께 떨어진 뒤 0번 방으로 돌아간다.

‘리와인드’는 x=1500에서 최근 1.6초의 실제 위치·점프 궤적·방향·모션 프레임·플래시점프 잔상을 2.5배속으로 되감는다. 이후 조작 2.8초마다 되풀이되며, 직전 잔상이 몸으로 모이는 0.35초 예고가 있다. 되감는 동안 조작을 잠시 막고 끝나면 누르고 있던 방향과 복원한 물리 상태로 이어 간다. 되감기 자체는 기록하지 않아 매 주기 탈출 쪽으로 전진할 수 있다.

‘도망가는 출구’는 오른쪽 문에 접근하면 그 문이 먼저 오른쪽으로 달아난다. 이 모습을 본 뒤 왼쪽 문까지 되돌아와 접근하면 왼쪽 문과 방 번호도 도망간다. 오른쪽 문이 움직이기 전에는 왼쪽 문이 따라오거나 피하지 않는다. 접근하면 0.035초 뒤 첫 회피는 440만큼, 이후에는 340만큼 빠르게 피한다. 회피는 0.48초 동안 진행되고, 첫 회피 뒤 0.65초·이후 0.4초 동안 잠깐 멈춘다. 보통 연속 플래시점프 세 번 안팎에 따라잡도록 거리와 시간을 맞췄으며, 별도의 횟수 조건 없이 실제 접촉으로 판정한다. 플레이어가 48만큼 물러나면 문은 피하기 전 자리로 돌아오며, 그동안 다시 접근해도 복귀를 취소하지 않는다. 문이 쉬거나 돌아오는 순간 플래시점프로 닿으면 맵 끝을 지나지 않고 다음 방으로 이동한다. 양쪽 문 모두 회피 횟수와 이동 위치에 제한이 없어 보행만으로 따라가면 문이 계속 피한다. 추격하는 쪽으로 통로와 카메라가 끝없이 이어지며, 배경은 화면에 보이는 구간만 반복해 그린다. 이상이 드러난 뒤에는 원래 맵 경계를 넘는 것만으로는 전환하지 않는다. 왼쪽 문을 잡으면 다음 방으로, 오른쪽 문을 잡으면 오답으로 0번 방에 돌아간다. 스크롤·확대 두 현상은 제거했다.

‘전체 선택 → 삭제’는 x=1100에서 파란 선택 영역이 오른쪽부터 3.6초 동안 다가오고, 0.55초 멈춘 뒤 한 번에 지워진다. 삭제 경계(x=450) 오른쪽에 몸이 남으면 캐릭터도 지워지고 0번 방으로 돌아간다. 선택이 지워지기 전에는 접촉해도 안전하며, 캐릭터가 살아남으면 빈 공간의 흰 입력 커서 옆에 붉은 ‘아...깝...다...’가 머뭇거리듯 입력되고, 커서는 글자 끝으로 이동하며 깜빡인다. 삭제에 잡히면 화면 전체를 검게 지우고 커서만 남긴 뒤 0.85초 후 0번 방으로 복귀한다.

‘로딩 중’은 방에 들어오자마자 게임 화면 중앙에 28px 회색 CSS 스피너와 `Loading…`, 옅은 로딩 막을 표시한다. 이동 입력은 그대로 가능하다. 3.2초 뒤 당시 화면 중앙을 흡수 지점으로 고정하고, 2초 동안 흡입력을 높인다. 배경이 로딩 표시 쪽으로 휘고 실제 배경 조각과 캐릭터가 끌려간다. 가까이 빨려들면 0.85초 동안 작아져 사라진 뒤 0번 방으로 돌아가며, 이전의 회전·발사·추격은 없다. 왼쪽 플래시점프로 흡수에서 벗어나 출구까지 돌아갈 수 있다. 표시 크기는 게임 배율과 무관한 CSS 픽셀로 유지하고, 연출 시간은 게임 시각을 따라 탭 비활성화 시 멈춘다.

‘문에 끼어 있는 침입자’는 기존 ‘다른 방의 침범’을 교체한다. 시작·출구와 같은 회색 연구소 문 리소스를 사용한다. x=1000에서 좁은 문틈에 회갈색 손가락 세 개가 서로 다른 길이로 걸린다. 마디와 납작한 손톱이 보이며 대부분 멈춰 있다가 가운데 손가락만 한 번 살짝 움켜쥔다. 문과 비슷한 색과 접촉 그림자로 전조의 대비를 낮춘다. 돌출한 손은 네 손가락과 옆으로 갈라진 엄지, 힘줄과 굵기가 달라지는 마디를 구분해 그린다. 손가락을 최소 2.1초 보여준 뒤 x=1250까지 접근하면 0.62초 동안 틈에서 버티고, 손이 문짝을 밀치며 0.28초 동안 먼저 튀어나온다. 몸은 손이 나오기 시작한 뒤 0.18초 늦게 따라 나와 작은 입구에 걸린다. 몸과 관절은 Canvas로 그리고 인형 얼굴·괘종시계 내부·의자 목재 조각을 붙였다. 손에 실제 접촉하면 조작을 잠그고 1.15초 동안 문 안으로 끌고 간 뒤 0번 방으로 돌려보낸다. 첫 왼쪽 공격을 피하면 0.32초 동안 팔을 거두고 0.22초에 걸쳐 문 중앙을 축으로 좌우반전한다. 0.18초간 반대편을 향해 버틴 뒤 오른쪽으로 같은 공격을 한다. 양쪽 모두 손과 캐릭터의 실제 이동 궤적으로 판정하며 방향 전환·팔 회수 중에는 잡지 않는다. 두 공격을 모두 피하면 팔과 몸이 문 안으로 물러나고 문이 닫힌다. 해당 방에서는 다시 공격하지 않으며, 왼쪽으로 돌아 나가면 다음 방으로 진행한다. 추가 다운로드와 소리는 없다.

### 이상현상 검토 목록

개발 모드(`?dev=1`)의 선택 상자에서 모두 재생할 수 있다. 발동 안내는 개발 모드에만 표시한다. 낙하 배관에 맞거나 화면 추격에 잡히면 0번 방으로 돌아간다. 급강하 천장은 붉은 피격 효과 없이 캐릭터를 납작하게 누른 뒤 0번 방으로 돌려보낸다. 기존 연구소 리소스와 main에서 가져온 개폐 철문·저택 리소스를 사용하며 추가 다운로드는 없다.

웹 공간 이상현상도 방향키·Alt만 사용한다. 화면 밖으로 나가는 현상은 x=2100 이후 오른쪽 플래시점프에서 발동하며 카메라가 멈춘 구간에서 페이지 여백을 사용한다. 화면 밖에 나가면 1.25초 동안 화면이 떨리며 안으로 돌아올 유예를 준다. 밖에 나가지 않았더라도 경계가 열린 뒤 가장 오른쪽으로 간 위치에서 왼쪽으로 100만큼 되돌아가면 추격이 시작된다. 밖에 나갔다면 기존처럼 복귀 시 시작한다. 추격 중에는 오른쪽 경계가 왼쪽으로 좁혀 오고 정지 상태에서 초당 최대 416까지 가속한다. 가속도와 최고 속도는 이전보다 20% 낮췄다. 방향키를 누르며 Alt 플래시점프를 이어 쓰면 왼쪽 출구까지 탈출할 수 있지만 보행만으로는 잡힌다. 유예를 놓치거나 경계에 잡히면 회전·낙하 뒤 0번 방으로 돌아가고 번호가 지직거린다. 추격을 피하면 정상적으로 다음 방으로 진행하며 7 → 8도 직접 조작하는 출구 방으로 연결된다. 캐릭터·그림자·잔상은 원래 화면과 동일한 좌표·물리·프레임을 공유한다. ‘연구소의 뒷면’은 이동 위치에 따라 CSS 3D 벽 세 장이 돌아가고, 앞면·보강재가 있는 뒷면·모서리·바닥 그림자가 함께 변한다. 벽에 가려지는 동안에도 조작은 유지된다. 뒷면의 작은 문에 다가가면 천천히 열리며 현재 번호의 시작 입구를 보여준다. 이상을 본 뒤 왼쪽으로 되돌아오면 입구 쪽 벽 두 장도 반대 경첩을 축으로 열리고 왼쪽 문틈에 같은 번호의 입구가 나타난다. 처음 입장할 때는 귀로 연출이 숨겨져 안내판을 가리지 않는다. 귀로의 문에 도달하면 맵 끝까지 지나가지 않고 다음 방으로 전환한다. 양쪽 문틈은 같은 방에서 왕복해도 유지되고, 바닥의 빛과 벽을 잡는 케이블이 공간감을 더한다. 새 방·개발 재선택·8번 방에서는 페이지 연출이 정리된다.

### 조작과 실행

```sh
npm run dev
```

[게임](http://127.0.0.1:8000/src/games/laboratory/)에서 화면을 누른 뒤 `←`·`→`로 이동하고 `Alt`로 점프한다. 공중에서 `Alt`를 한 번 더 누르면 바라보는 방향으로 플래시점프한다. 착지하면 다시 사용할 수 있다. 누르고 있는 Alt의 자동 반복은 추가 점프로 처리하지 않는다. 화면 아래 버튼은 누르는 동안 이동하며 점프 버튼을 두 번 눌러 플래시점프할 수 있다.

[개발 모드](http://127.0.0.1:8000/src/games/laboratory/?dev=1)는 정확히 `?dev=1`일 때만 표시된다. 상황을 선택하면 선택한 상황의 0번 방에서 위치·진행도·이상현상 발동·방 전환을 초기화한다. 다음 통로도 같은 상황을 유지하며, ‘선택 상황 다시 시작’으로 재현할 수 있다. ‘일반 진행 · 무작위’는 정상 0번 방부터 다시 시작한다. ‘8번 방 확인’은 현재 방 진행을 건너뛰고 실제 7→8번 방 전환을 재생하고 조작 가능한 8번 방으로 이동한다. 마주친 이상현상 기록은 보존한다. 이후 ‘선택 상황 다시 시작’으로 선택한 이상현상의 0번 방으로 돌아갈 수 있다. 일반 화면에는 이상현상 정답과 개발 정보가 표시되지 않는다.

- `src/games/laboratory/game.ts`: DOM과 무관한 플레이어 물리·판정·진행 상태. 120Hz 고정 간격으로 갱신한다.
- `assets.ts`: 기존 매니페스트의 C-2 배경과 모험가 프레임을 로컬에서 불러오고 보정한 배경을 캐시한다.
- `renderer.ts`·`anomaly-renderer.ts`·`chamber-renderer.ts`: 카메라·캐릭터와 이상현상 연출을 그린다.
- `escaping-exit.ts`: 입구의 회피·휴식·복귀와 이동 중 접촉 판정을 담당한다.
- `screen-selection.ts`·`browser-hazard-renderer.ts`: 선택 삭제 판정과 화면 연출을 담당한다.
- `loading-wheel.ts`·`loading-overlay.ts`: 로딩 흡수 규칙과 CSS 로딩 표시·왜곡 화면을 담당한다.
- `anomalies.ts`: 이상현상 목록·발동 안내·추첨 가중치를 정의한다.
- `web-space.ts`·`spatial-rules.ts`: 페이지 경계와 CSS 3D 표시·순수 좌표 규칙을 담당한다.
- `anomaly-motion.ts`: 방마다 새로 생성되어 시선 반응·지연 추적·소등 시간을 소유한다.
- `index.ts`: 입력·화면·개발 모드·실행 루프를 소유한다. 포커스를 잃으면 입력을 해제하고 탭이 숨겨지면 진행을 멈춘다.
- `npm test`: 빌드 후 Node 기본 테스트 러너로 이동, 착지, 플래시점프 제한, 이상 발동, 출구 판정, 개발 상황 재설정을 검증한다.

### 엔딩과 탐험 기록

- 8번 방은 오른쪽으로 갈수록 빛이 짙어진다. 캐릭터와 잔상이 모두 가려지는 지점에서 밝게 전환되며 엔딩으로 이어진다. 걷기·점프·플래시점프 모두 같은 위치 기준을 사용한다.
- 엔딩의 ‘마주친 이상현상’과 ‘크레딧’ 버튼으로 기록·리소스 출처를 조회하고 ‘다시 들어가기’로 새 탐험을 시작한다.
- 관찰 구간에 도달하거나 동작을 발동시킨 경우에만 기록한다. 화면 밖으로는 경계에서 플래시점프가 필요하다. 이상이 배정된 방에 들어가기만 하고 돌아온 경우는 기록하지 않는다. 기록은 실패해 0번 방으로 돌아가도 유지하며 중복은 제거한다.
- 기록은 현재 탐험 동안만 유지한다. 처음부터 시작, 개발 모드의 상황 재선택, 새로고침은 기록을 초기화한다. 아직 마주치지 않은 이상현상의 이름은 엔딩에 노출하지 않는다.

## 게임 설계 기준

- 구현 편의나 현상의 개수보다 발견·반응·기억에 남는 장면의 재미를 우선한다. 배경 질감, 움직임의 무게, 가림, 타이밍까지 실제 플레이로 검토하며 기능 구현만으로 완성으로 판단하지 않는다.
- 직관과 간결함을 우선한다. 감성적인 격려 문구는 쓰지 않고, 설명보다 관찰로 이해하는 경험을 만든다. 규칙은 맵 안 안내판에 짧게 적고, 진행은 문 위 번호로 보여준다.
- 정답·오답 해설, 반복 안내, 방마다 확인을 요구하는 팝업을 사용하지 않는다. 성공은 번호 상승, 실패는 번호 노이즈와 0으로의 복귀로 전달한다. 소리는 추가하지 않는다.
- 8번 방은 따뜻한 색감과 오른쪽으로 짙어지는 빛으로 구분한다. 빛 속으로 직접 나간 뒤 밝은 엔딩 화면에 ‘탈출 성공!’을 표시하고 이번 탐험의 이상현상 기록과 크레딧을 조회한다. 조작법은 화면 밖에 최소한으로 남기고, 상세 상태는 개발 모드에서만 제공한다. Canvas 안내와 방 번호는 화면 낭독기용 텍스트로도 제공한다.

- 이동·충돌·공격 판정과 Canvas 렌더링을 분리한다.
- 물리는 고정 시간 간격으로 계산하고, 렌더링은 `requestAnimationFrame`으로 실행한다.
- 시간은 초, 위치는 월드 픽셀, 속도는 월드 픽셀/초를 사용한다. 월드 좌표·화면 좌표·Canvas 실제 픽셀 크기를 구분한다.
- 키 입력은 `jump`, `attack` 같은 행동으로 매핑한다. 캐릭터 상태는 타입으로 정의하고 모션 전환과 일관되게 관리한다.
- 이동 속도·점프 높이·공격 범위는 설정으로, 프레임 시간·이미지 기준점·경로는 리소스 데이터로 관리한다. 충돌 영역은 이미지 크기와 별도로 정의한다.
- 점프 횟수 제한·발판 착지·피격 판정은 핵심 로직 테스트 대상으로 삼는다.

## 개발 도구

Node.js 요구 버전은 `package.json`의 `engines`를 따른다. 패키지는 npm과 `package-lock.json`으로 관리한다.

```sh
npm ci
npm run check
```

- `npm run lint`: JavaScript·TypeScript 코드 검사
- `npm run lint:fix`: 자동 수정 가능한 린트 문제 수정
- `npm run format`: 작은따옴표(`singleQuote: true`)를 적용하고 나머지는 Prettier 기본 설정으로 포맷
- `npm run format:check`: 파일 수정 없이 포맷 검사
- `npm run check`: 타입·린트·포맷 검사

[typescript-eslint 권장 설정](https://typescript-eslint.io/getting-started/)을 사용하고, [Prettier 설치 지침](https://prettier.io/docs/install)에 따라 버전을 고정한다. `eslint-config-prettier`로 포맷 관련 린트 충돌을 방지한다. 다운로드한 리소스와 생성물은 검사·포맷에서 제외한다.

## 리소스 뷰어 실행

```sh
npm ci
npm run dev
```

[리소스 뷰어](http://127.0.0.1:8000/src/resources/)에서 캐릭터별 화면으로 이동할 수 있다. `yeti/`, `slime/`, `adventurer/`에서 각각 모션을 선택하고 일시정지할 수 있다. 다운로드한 로컬 이미지가 필요하다. 리소스 뷰어는 모션 확인용이며, 이동·점프·플래시점프는 위 C-2 게임에서 플레이한다.

- `src/resources/`: 카테고리 선택 화면. `characters/`, `backgrounds/`, `props/`, `audio/`는 각 분류의 목록이며 해당 리소스 카드만 생성한다. `yeti/`, `slime/`, `adventurer/`에 각 캐릭터의 `index.html`과 `index.ts` 진입점을 함께 둔다.
- `src/resources/preview/`: 공통 미리보기 코드와 스타일. `preview.ts`의 `ResourcePreview`가 화면·이미지·실행 루프를 관리하고, `animation-player.ts`의 `AnimationPlayer`가 모션 전환과 프레임 계산을 담당한다. `preview-renderer.ts`는 전달받은 정보로 Canvas를 그린다.
- `npm run build`: TypeScript를 `dist/`에 컴파일
- `npm run typecheck`: `strict` 타입 검사
- 추가 개발 서버 패키지 없이 Python 3 기본 HTTP 서버를 사용한다. 소스 수정 후 `npm run build`와 브라우저 새로고침이 필요하다.
- 캔버스는 960 × 480 월드 좌표를 화면 크기와 DPR에 맞춰 표시한다. 예티·슬라임은 임시 140ms/프레임으로 재생하고 모험가는 원본 부위 데이터의 프레임 시간을 사용한다.

## 현재 상태

C-2 게임에서 모험가 이동·점프·플래시점프, 세 가지 상황, 출구 판정과 개발 모드를 플레이할 수 있다. 예티·슬라임·모험가의 개별 모션 뷰어와 세 배경의 색감 미리보기도 유지한다.

### 배경 색감 예시

- `/src/resources/corridor/`에서 제뉴미스트 연구소 2층 복도의 보정 전후를 비교한다. `?map=subway`는 커닝시티 지하철, `?map=laboratory`는 알카드노 연구소 C-2이며 상단 링크나 리소스 선택 화면에서 이동한다.
- 지하철은 상층 발판과 사다리를 제거하고 콘크리트 벽·문·신호등·선로를 재배치했다. C-2는 상자 발판을 제거하고 문을 같은 높이에 배치했으며 배관·제어판을 합성했다. 모두 단층 분위기 검토용이며 원본 맵 구조를 그대로 재현하지 않는다.
- 복도 위치, 채도, 밝기, 차가운 색감, 가장자리 어둠을 조절한다. 정적 분위기 예시이며 NPC·소리·게임 조작은 포함하지 않는다.
- 맵 오브젝트 이미지의 흰색 바탕은 제거하고 벽면을 Canvas로 합성한다. 원본 톤도 같은 벽면을 사용하므로 실제 게임의 완전한 원본 배경은 아니다.
- 로컬 이미지: `public/assets/maplestory/` 아래 `zenumist-corridor/`, `kerning-subway/`, `alcadno-lab/`. 출처·크기·사용 구간·공식 개별 리소스는 `resources/manifest.json`의 `map/261010100`, `map/103000200`, `map/261020400` 항목에 기록한다.
- 조각 추출·재배치는 `industrial-renderer.ts`, 배경별 제목·보정 기본값은 `background-presets.ts`에서 관리한다. 동일한 Canvas 색 보정과 좌우 탐색을 세 배경에서 재사용한다.
- 다운로드 파일은 Git에서 제외한다. 새 체크아웃에서는 해당 항목과 `components`의 `imageUrl` 이미지를 각각의 `localPath`에 저장해야 한다.

## 모험가 리소스

- 외형: 검은색 토벤 머리, 자신있는 얼굴 (검은 눈), 크림 피부, 하얀 반팔 면티, 파란 청 반바지, 빨간색 장화.
- 공식 검색 API에서 부위 7종을 확인했다. 아바타 렌더 API는 404를 반환해 부위별 아틀라스와 소켓·zmap을 이용해 PNG 프레임을 로컬 합성했다.
- 대기(`stand1`), 걷기(`walk1`), 점프(`jump`), 맨손 공격(`swingO1`), 피격 대체(`alert` 자세 + `hit` 표정)를 제공한다. 피격 대체는 원본의 독립적인 피격 동작이 아니다.
- 원본 아틀라스, 부위 메타데이터, 합성 프레임은 `public/assets/maplestory/adventurer/`에 보관한다. 각 부위의 출처·ID와 프레임 기준점·시간은 `resources/manifest.json`에서 관리한다.

## 저택 공포게임 리소스 묶음

- `/src/resources/haunted-house/`에서 분류별 원본 이미지와 활용 메모를 확인한다. 파일·프레임 정보를 펼치면 모든 프레임을 정적으로 비교하고 원본 PNG를 열 수 있다. 자동 애니메이션 재생은 하지 않는다. 개폐 철문은 두 상태를 나란히 표시하며, 효과음은 기본 음량 35%의 오디오 컨트롤로 직접 재생한다.

- `resources/manifest.json`의 `collection: haunted-house`로 이미지 16종·효과음 4종을 모았다. 이름은 식별하기 쉬운 프로젝트 표시명이며, 출처는 각 항목의 `sourceUrl`에서 확인한다.
- 공간: 저택 실내 벽, 목재 바닥 무늬, 장식 양문, 깨진 창문, 개폐 철문.
- 소품: 작은 초상화, 목재 괘종시계, 낡은 나무 의자, 남겨진 인형, 목재 책장, 목재 벽거울.
- 조명·단서: 벽 촛대, 낡은 열쇠, 쪽지, 해골 촛불. 위협: 유령의 대기·이동·추격 모션.
- 원본 PNG 47프레임·OGG 효과음 4개와 조회 메타데이터는 `public/assets/maplestory/haunted-house/`에 보관한다(약 1 MB, Git 제외). 기존 다운로드를 재사용하며 게임 실행 중 CDN을 조회하지 않는다.
- 정적 리소스도 `animations.stand.frames`에 한 프레임으로 기록한다. 모든 프레임의 크기·왼쪽 아래 기준점·원본 URL·로컬 경로를 저장했다. 모션의 원본 재생 시간은 미확인이며 임의의 시간을 원본 정보로 기록하지 않는다.
- 완성된 맵이나 동일 맵에서 추출한 세트는 아니다. 크기·색감·반복 연결은 게임 배치 시 조정한다. 바닥은 표면 텍스처, 기존 장식 양문은 닫힌 상태만, 벽 촛대는 불꽃 없는 이미지다. 새 개폐 철문은 다른 디자인의 6프레임이며 `states`에 닫힘·열림의 프레임 위치를 기록했다. 해골 촛불은 초와 불꽃이 합쳐진 4프레임으로 독립 광원용이다. 세부 활용과 제약은 각 항목의 `notes`에 기록했다.
- 다른 체크아웃에서는 프레임의 `sourceUrl` 파일을 해당 `localPath`에 저장한다. 로컬에 원본이 있다면 복사해서 재사용한다.

- 효과음: 문 삐걱임, 나무 바닥 발소리, 시계 째깍임, 문 노크. `audio`에 원본 URL·로컬 경로·재생 시간·출처 설명·메타데이터 경로를 기록한다. 설명을 기준으로 고른 후보이며 실제 분위기와 반복 간격은 청취 후 결정한다. 자동 재생·자동 반복은 하지 않는다.

## 리소스 분류와 출처 표시

- 첫 화면 `/src/resources/`는 카테고리별 개수와 테마 링크만 표시하고 이미지·오디오 카드를 생성하지 않는다. `characters/`, `backgrounds/`, `props/`, `audio/`의 독립 페이지가 `manifest.json`의 `category`로 목록을 골라 표시한다. 상단 메뉴로 다른 분류에 이동할 수 있다. `collection`은 저택 같은 테마 묶음이며 기본 분류와 별개다.
- 모든 카드에 `sourceName`과 `sourceUrl`을 표시한다. 확인된 원본 이름은 `originalName`, 기존 상세 뷰어 경로는 `previewPath`에 기록한다. 미확인 원본 이름은 추측하지 않고 리소스 ID로 구분한다.
- 모험가의 합성 부위와 재배치 배경의 추가 소품은 `components`의 출처 링크로 확인한다. `composition`에 원본과 다른 가공 내용을 표시한다. 맵 원본 이미지는 MapleDB, 추가 구성 리소스는 메이플스토리 월드 출처를 구분한다.
- `src/resources/catalog/`의 카드와 스타일을 각 카테고리 목록과 저택 테마 화면에서 함께 사용한다. `categories.ts`는 카테고리 메뉴를, `category-page.ts`는 해당 분류의 카드 생성을 담당한다. 원본 파일·프레임 정보를 복제하지 않으며 기존 상세 뷰어 주소도 유지한다.
