# 이어진 골목 · 연결형 모듈

작은 항구의 집을 이어서 닫힌 도장 아래 길과 안마당을 만드는 독립 시안. 이전 블록 마을과 달리 동일한 기존 건물의 외벽·지붕·통행 형태가 이웃 배치에 따라 바뀐다.

## 참고와 직접 작성한 부분

- [Townscaper 공식 소개](https://www.townscapergame.com/)는 불규칙 격자에 놓은 블록의 배치에 따라 집·아치·계단·다리·마당이 자동 구성된다고 설명한다. 이 시안은 그 인접 규칙을 참고했다.
- 자체 규칙은 작은 정사각 격자의 11 → 13 → 16개 모듈만 다룬다. 공식 게임의 알고리즘을 재현한 것이 아니다.
- 각 모듈은 비어 있는 이웃 방향에만 외벽과 처마를 만든다. 연결 면의 외벽·처마가 없어지고 지붕 중심 면이 이어진다. 중앙 도장의 좌우가 채워지면 기존 건물을 실제 아치 개구부를 가진 extrusion으로 교체한다.
- 공유 벽은 8 → 12 → 20쌍, 외벽은 28 → 28 → 24면으로 바뀐다. 마지막 안마당 폐합에서 꽃과 발판이 생긴다. 배치와 규칙은 `layout.ts`, 렌더는 `scene.ts`가 소유한다.
- 포장 무늬·창문·타일·간판은 CanvasTexture로 직접 작성했다. 창과 간판은 건물 로컬 면에 붙이고 카메라를 따라 회전시키지 않는다. 외부 그림·게임 모델·다운로드·유료 생성은 사용하지 않았다.
- 아타호는 기존 `ai/tiger-hero`의 승인된 RGBA 프레임을 재사용한다. 원본 width/height/pivot과 색·투명도를 유지하며 수직 billboard의 yaw만 맞춘다. 카메라 높이로 줄어드는 투영 세로 비율만 보정한다.

## 실제로 비교할 내용

화면의 길을 누르거나 WASD/방향키로 걷고, Space 또는 시설 사용 버튼으로 가까운 시설을 사용한다. 처음엔 중앙 도장이 막혀 있어 옆 골목으로 돌아 안쪽 쉼터에 도착한다. 도장에서 집을 잇거나 상단 버튼을 누르면 중앙 아치가 열려 직선 통행이 가능해진다. 한 번 더 잇으면 안마당이 완성된다.

`R`과 도장 잇기 버튼은 세 배치를 순환한다. `M`은 전체 조망, Esc는 멈춤, 입구로 버튼은 현재 증축과 방문 기록을 남기고 돌아간다. 화덕에서 불을 지피고 도장을 잇고 쉼터를 사용한 뒤 입구로 돌아오면 한 바퀴가 완성된다. 증축/분리로 새 벽 내부에 겹친 플레이어는 안전한 입구로 옮긴다.

실제 보행 접근점:

| 지점             |    x |     z |
| ---------------- | ---: | ----: |
| 입구             |    0 |   7.5 |
| 나루 차 화덕     | -4.9 |  4.45 |
| 도장 앞          |    0 |  2.25 |
| 열린 아치 안     |    0 |     0 |
| 안쪽 마당 쉼터   |    0 |  -2.6 |
| 분리 단계 우회점 | 1.56 |  1.56 |
| 분리 단계 우회점 | 1.56 | -1.56 |

아치 안은 연결/완성 단계에만 보행 가능하다. 같은 인접 표와 플레이어 반경을 경로 탐색 및 직접 입력 충돌에 사용한다. 단순 그림 교체 뒤 충돌을 별도로 남기지 않는다.

## 관측과 수명

`window.villageStyleModular`는 읽기용 상태만 제공한다. `ready`, `snapshot.player`, `snapshot.stage`, `paused`, `overview`, `disposed`, `screenPositions`, `project({x,z})` 및 `diagnostics`가 있다. `diagnostics`의 모듈 수·공유 벽·외벽·아치·마당·geometrySignature·rebuilds는 증축 재구성을 확인하기 위한 정보다. 상태 변경 API는 제공하지 않는다.

`?embed=1`은 설명 머리말만 줄이고 모든 조작을 유지한다. 처음 들어갈 때 포커스를 가져오지 않는다. 멈춤은 이동·화덕 시간·연기·스프라이트와 증축 입력을 함께 멈춘다. `resource-scene-dispose` 및 pagehide는 이벤트·RAF·GPU 자원을 해제한다.

## 검증

- `npm run check`, `npm run build` 통과.
- 당시 로직 검사 5개 통과: 인접 형태 변화, 통행 경로 단축, 시설 한 바퀴와 기록, 증축/분리 끼임 보정, 보행·화덕·잘못된 입력.
- 설치된 실제 Chrome에서 키보드 이동과 캔버스 좌표 클릭으로 화덕 → 도장 → 아치 통행 → 안마당 → 귀환을 검증했다. 세 배치 geometrySignature와 통행 변화, 닫힌 아치 안 플레이어의 안전 보정도 확인했다.
- 정지 뒤 500ms 동안 실제 snapshot과 canvas PNG 픽셀이 동일함을 확인했다. 390×620 라이브러리 iframe 형태와 1100×620, deviceScaleFactor 2의 실제 좌표 클릭을 확인했다. 이는 실제 휴대전화 검증은 아니다.
- 초기 포커스·embed 버튼·콘솔 오류·dispose 뒤 시간 정지를 확인했다. 첫/완성 단계 검토 그림은 `/private/tmp/modular-stage-0.png`, `/private/tmp/modular-stage-2.png`, 실제 플레이 그림은 `/private/tmp/modular-stage-2-play.png`, 좁은 화면은 `/private/tmp/modular-narrow.png`에 저장했다.

통합 담당자가 `library-entry.json`을 리소스 manifest에 등록하고 실제 캡처와 출처를 보관한다. 이 시안은 본게임에 연결하지 않는다.
