# 열린 집들 · 단면 마을

외벽을 잘라 집의 하루를 드러내는 독립 보행 시안이다. 공방·재료방·부엌·도장·다락 숙소의 다섯 실내를 뒤벽, 가구, 주민, 앞 복도로 나눠 그린다. 서로 다른 높이의 두 집은 2층 복도와 세 대각 계단으로 이어진다. 전체 조망에서는 지붕과 절단면 두께, 주민 생활, 실제 이동 경로를 함께 확인한다.

## 참고에서 확인한 사실과 직접 구현

- [Bethesda 공식 Fallout Shelter 소개](https://fallout.bethesda.net/en/games/fallout-shelter)는 지하 Vault와 주민이 있는 여러 방의 운영을 소개한다. [공식 제작 지원 문서](https://help.bethesda.net/app/answers/detail/a_id/34931/)는 제작방 건설과 방 단계에 따른 제작 범위를 설명한다. 방의 단면 구성과 내부의 생활·시설 변화가 보이는 방식만 시각 참고했다.
- 해당 게임의 내부 렌더링·길찾기 기술은 확인하지 않았다. 이 시안의 Canvas2D 레이어, 3층 복도 연결망, 대각 계단 최단 경로는 프로젝트에서 직접 구현한 제안이다. 본게임의 경제·전투·성장·저장은 연결하지 않는다.
- 환경의 지붕·잘린 외벽·창·판자·책장·화덕·작업대·침대·수련 장비·주민·식생은 `drawing.ts`에서 직접 그렸다. 외부 게임 이미지나 모델을 복사하지 않았고 새 패키지·유료 생성 작업을 추가하지 않았다.
- 아타호는 기존 `ai/tiger-hero`의 승인된 대기와 좌우 보행 프레임을 사용한다. 원본 RGBA를 변형하거나 필터를 씌우지 않는다. 원본 폭·높이에 같은 배율을 적용하고 `pivot.x`와 발 기준 `height - pivot.y`로 붙여 발 접지를 유지한다. 각 프레임은 원본 로컬 PNG 그대로 로딩한다.
- 3D 오브젝트에 그림을 붙이는 시안은 아니다. 방 그림과 인물 그림을 같은 평면의 공간 좌표로 합성해 단면 마을에 적합한 2D 구성 방법을 비교한다. `외벽 비교`는 절단면을 닫았을 때 생활 공간이 얼마나 가려지는지 보여준다.

## 답사와 선택의 반응

입구 → 1층 공방 화덕 → 왼쪽 안쪽 계단 또는 오른쪽 바깥 계단 → 2층 도장 → 위층 계단 → 다락 숙소 → 바깥 계단 귀환의 짧은 답사를 한다. 화덕을 쓰면 불꽃·작업 주민의 손이 반응한다. 도장을 복구하면 상자가 사라지고 매트·장비·밝은 조명과 수련 주민이 들어온다. 다락에서 차를 마시면 김과 발견 문구가 나타난다. 계단 선택으로 재료방을 지날지 부엌을 지날지가 달라진다. 긴 경영·성장 루프의 재미를 검증한 시안은 아니다.

- 길 누르기 / 터치: 복도와 계단을 따라 보행한다. 방 안을 누르면 가장 가까운 복도에 보정한다. 위층 방을 눌러도 계단을 통해 실제로 올라간다.
- WASD / 방향키: 화면을 누른 뒤 직접 보행한다. 좌우는 복도를 걷고, 계단 입구·중간의 위아래는 해당 계단을 오르내린다. 계단이 없는 위치에서 위 방향키를 눌러도 층을 넘지 않는다.
- Space / 시설 사용: 같은 층의 가까운 시설을 사용한다. 도장에서는 복구 전후를 바꾼다.
- R / 도장 복구: 도장 사용과 같은 복구 상태를 바꾼다.
- M / 전체 조망: 집 전체와 가까이 걷기를 비교한다.
- Esc / 멈춤: 위치, 경로, 반응 시간, 주민·빨래·불꽃·차 김을 모두 멈춘다. 멈춤 중 복구·입구·시설·시점 입력도 반영하지 않는다.
- 입구로: 보행 위치와 경로만 되돌린다. 복구와 방문 기록은 유지한다.

라이브러리 `?embed=1`에서는 설명만 줄이고 복구·조망·멈춤·입구·외벽 비교·시설 버튼은 유지한다. 초기 키보드 포커스는 가져오지 않는다.

## 좌표와 수명

읽기 전용 `window.villageStyleCutaway`는 `ready`, `snapshot`, `paused`, `overview`, `disposed`, `diagnostics`, `project(point)`, `screenPositions`를 제공한다. 외부에서 상태를 직접 바꾸는 API는 없다. 반환되는 snapshot은 내부 상태와 분리된 복사본이다.

- `x`는 화면 오른쪽으로 증가한다. `z`는 깊이가 아니라 **위쪽으로 증가하는 높이**다. 1층 `z=0`, 2층 `z=4`, 3층 `z=8`이며 계단 중간에서는 연속 높이값을 갖는다. `snapshot.floor`는 0부터 센 층 번호다.
- `project({x,z})`와 `screenPositions[].screen`은 Canvas 내부 CSS 픽셀이다. 시점 버튼을 누른 뒤 다음 렌더 프레임의 좌표를 읽는다.
- 시설 보행 접근점: 공방 화덕 `(-10,0)`, 2층 도장 `(8,4)`, 다락 쉼터 `(3,8)`. 모두 실제 복도 위의 점이다.
- `diagnostics`는 층 높이·층 수·복도 연결 수·계단 수·현재 위치·층·가까운 시설·외벽 상태를 보여준다.
- 화면 객체가 RAF, 입력 리스너, ResizeObserver, 그림 캐시를 소유한다. `resource-scene-dispose`와 `pagehide`에서 함께 정리한다.

## 리소스와 검증

새 ignored 환경 미디어는 없다. `public/assets/maplestory/tiger-hero-ai/`의 기존 승인 아타호 PNG를 워크트리의 읽기 symlink로 재사용한다. 라이브러리 썸네일은 통합 담당자가 최종 Canvas를 실제 캡처하여 등록한다.

- `npm run check`, `npm run build`, `tests/village-style-cutaway.test.mjs`의 핵심 규칙 5개가 통과했다. 층 순간이동 방지, 계단 경로, 세 시설 실제 도착, 타이머, 입구 복귀의 기록 보존을 검사했다.
- 실제 Chrome의 1100/390 CSS 폭 × 620 높이 iframe에서 키보드 보행과 세 시설 포인터 답사, Space, 복구·외벽 비교·정지 입력·입구 복귀·종료 이벤트, 버튼 노출과 가로 넘침을 검사했다. 마지막 전체 조망 보정 후 다시 확인했다.
- 390 폭 DPR2 터치 iframe에서도 세 층을 실제 탭으로 답사하고 주민·차 김 그림의 시간 변화, 멈춤 중 동일한 Canvas 픽셀, `pagehide` 정리를 확인했다. 실제 휴대전화 검증을 뜻하지 않는다.
- 전체 조망의 지붕과 초기 인물, 좁은 화면의 가까이 보기를 실제 스크린샷으로 검토했다. 브라우저 예외·console error는 없었다.
