# 이끼 품은 둥지 · 자연입체·콜라주 조합

앞 뿌리는 씨앗 화덕에서 속 빈 줄기 마당의 버섯 도장으로 이어진다. 뒤 뿌리는 더 높고 좁은 굴곡을 따라 이끼 뒤 쉼터에 닿는다. 쉼터를 발견하면 돌아가는 길에 푸른 포자가 켜진다. 작은 마을의 답사·복구·돌아오기만 구현한 독립 시안이다.

## 재사용한 원리와 새로 전환한 작업

- 기존 `village-style-natural`은 높이 함수가 있는 자연 지형, 실제 입체 건축·그림자, 저해상도 렌더와 수직 원본 도트 인물을 보여줬다. 이 시안은 그 원리를 사용하지만 기존의 각진 초록 광장 메시를 색만 바꾸지 않았다. 두 갈래 곡선의 표본·폭·높이와 줄기 안 마당으로 새 공간을 작성했다.
- 기존 `village-style-collage`는 껍질 결·이끼·버섯 반점의 소재판을 2D 윤곽에 제한하는 Canvas 합성이었다. 큰 줄기와 뿌리의 두께도 2D 그림이었다. 여기서는 작성한 소재판을 실제 메시의 UV로 옮겼다. 중앙은 노출 껍질, 가장자리는 이끼이며 껍질 UV의 결은 뿌리 중심선 방향을 따른다. 소재판은 사진 촬영이나 원작 게임 미디어가 아닌 이 폴더의 코드다.
- 뿌리 윗면은 `rootHeight()`를 쓰는 메시다. 옆면은 6단으로 부풀었다가 중심선 쪽으로 접혀 아랫면에서 가늘어진다. 속 빈 줄기 벽은 실제 두께 0.68, 열린 앞면과 다른 높이의 윗단을 가진다. 버섯 지붕은 회전체 메시이며 반점 소재와 옆면·그림자가 함께 보인다. 큰 외곽은 geometry가 만들고 무늬가 외곽을 대신하지 않는다.
- 잎·늘어진 이끼는 3D 본체 위치에 고정한 알파 판이다. 카메라를 향해 계속 돌리지 않는다. 뒤 뿌리 위를 걷는 아타호를 이끼가 깊이 순서로 가린다. 원경은 굵기·기울기·가지·수관이 다른 입체 나무이며 플레이 공간 앞에 수관을 겹치지 않게 했다.
- 기존 `village-style-lit2d/normal.ts`의 높이장→normal 순수 계산을 재사용했다. 껍질·돌·이끼·버섯의 albedo와 normal은 같은 UV/96×96 단위다. 색 지도는 sRGB, normal 지도는 색 변환을 하지 않는 데이터다. 실제 Three.js PointLight가 화덕 옆 돌과 껍질에 부분적인 명암을 만들며 N/요철과 L/불빛 버튼으로 비교한다. normal은 표면 방향 정보이고 큰 굴곡이나 외곽을 만들지 않는다. [Three.js 공식 MeshStandardMaterial 설명](https://threejs.org/docs/pages/MeshStandardMaterial.html).
- 아타호는 승인된 `ai/tiger-hero` 대기·보행 4방향 36개 원본 RGBA 프레임을 재사용한다. 가로·세로·아래 기준 pivot을 보존한다. `TrailSprite`의 `frame-pivot` 배치를 사용하며 판은 수직 yaw만 카메라 방향으로 회전한다. 카메라 pitch로 줄어드는 투영 높이를 보정해 원본 비율을 유지한다. 새 아트·유료 생성·추가 패키지 없이 기존 로컬 리소스와 Three.js를 사용한다.

## 공간·규칙의 공유와 조작

곡선 표본과 폭은 보행 가능 영역과 메시 외곽의 같은 기준이다. `rootHeight()`가 메시 정점과 인물 접지 높이를 함께 제공한다. 클릭은 현재 카메라의 광선을 같은 뿌리 윗면 메시와 교차시켜 얻고, 경로 탐색은 보행 폭·줄기 벽·시설 충돌을 공유한다. 큰 뿌리의 높은 뒤길에서도 클릭과 발 접점이 맞는다.

WASD/방향키 또는 뿌리 윗면 클릭으로 걷는다. 화면을 누르기 전에는 포커스를 가져가지 않는다. Space/시설 사용, R/도장 복구, M/전체 조망, N/요철 비교, L/불빛 비교, Esc/멈춤을 제공한다.

| 장소         | 실제 접근점 `(x,z)` | 반응                                     |
| ------------ | ------------------- | ---------------------------------------- |
| 입구         | `(-9, 5)`           | 입구 복귀 위치                           |
| 씨앗 화덕    | `(-5.2, 3.6)`       | 12초 불꽃·온기, 주변 껍질·돌의 요철 명암 |
| 버섯 도장    | `(-0.3, -0.1)`      | 지붕 잎 패치·포자 등 복구                |
| 이끼 뒤 쉼터 | `(4.4, -4.5)`       | 숨은 길 발견·돌아가는 뒤 뿌리 포자 표시  |
| 높은 뒤 뿌리 | `(0, -5.7)`         | 입구보다 약 1.5 높은 보행면              |

입구 복귀는 방문·발견·복구·누적 시간을 유지한다. 정지 중에는 입력·시간·원본 애니메이션·PNG가 멈춘다. 정지 중 크기를 바꾸면 마지막 상태를 한 번 다시 렌더해 화면 비율을 유지한다. `?embed=1`에서는 설명만 숨기며 시설·복구·시점·요철·불빛·멈춤·입구 버튼은 유지한다.

## 확인된 사실과 제안·부작용

실제 geometry의 높이·옆면·두꺼운 줄기 벽과 PointLight 그림자가 있어 기존 2D 콜라주의 화면 확대/이동과 다른 공간 정보를 보여준다. 소재 밀도를 전부 같게 만들지 않고 줄기 껍질, 보행 중앙 껍질, 가장자리 이끼, 돌, 버섯 반점을 구분하면서 팔레트와 픽셀 단위를 맞췄다. 처음 넓은 녹색 판으로 읽히던 초안을 담당 세션의 PNG 검토 후 노출 껍질·둥근 옆면으로 개선했다.

현재 확인 범위는 독립 브라우저 답사다. 본게임의 전투·경제·저장·성장·캐릭터 이동은 연결하지 않았다. 이후 본게임에 채택한다면 높이 보행과 작은 통로의 카메라/가림 규칙을 연결해야 한다는 것은 제안이며 이번 구현의 확인 사실과 구분한다. 저해상도 렌더는 세밀한 소재의 손실과 알파 판 가장자리 계단을 만들 수 있고, 두 시점에서 고정 이끼의 가림 범위가 달라진다. 이 결과를 실제 조작으로 검토한다.

## 수명과 통합 규격

`resource-scene-dispose`와 `pagehide`에서 RAF·이벤트·ResizeObserver·인물 텍스처·작성 소재 Canvas·geometry/material·shadow·WebGL context를 정리한다. 초기 로딩 중 종료되어도 늦게 도착한 인물 텍스처를 폐기한다.

읽기 전용 `window.villageStyleMixedForest`는 첫 렌더 뒤 `ready`, `snapshot`(`position {x,z}`, 높이·방향·보행을 가진 `player`, `nearby`, `visited`, `restored`, `discovered`, `fireSeconds`, `elapsed` 등), `paused`, `overview`, `disposed`, `project({x,z})`, `screenPositions`, `diagnostics`를 제공한다. project는 Canvas 내부 CSS 좌표, screenPositions는 시설 몸체 대신 실제 접근점이며 중첩 객체도 동결한다. diagnostics는 실제 메시/높이 공유, 둥근 아랫면, material/normal/light, 원본 프레임 수·크기·pivot·yaw·pitch 보정과 현재 발 높이·렌더 크기를 제공한다. 외부 상태 변경 API는 없다.

## 검증

- 핵심 로직 테스트 6개: 높이 차이·허공/줄기/시설 충돌, 두 갈래 순환과 시설 접근·복구·발견, 화덕 시간과 아래 pivot, 껍질/돌 normal 광원 반응, 비교 상태와 동결 snapshot, 몸체 옆 키보드→클릭 격자 합류.
- `npm run check`, `npm run build`, `node --test tests/village-style-mixed-forest.test.mjs`가 통과했다.
- 설치된 Playwright와 실제 Google Chrome, 1100×620/DPR2에서 키보드→클릭 이동, 화덕→높은 뒤 쉼터→줄기 도장 순환, 시설 3/3 사용, 도장 복구·숨은 쉼터 발견·입구 복귀 기록 보존을 검증했다. 약 46.0 거리 보행, 화덕 발 높이 0.893/지면 0.863, 뒤 쉼터 발 높이 1.888/지면 1.858로 접지 간격 0.03을 유지했다. 실제 높은 길과 조망에서 줄기 벽·뿌리 옆면·그림자를 검토했다. 뒤 쉼터 PNG에서 원본 인물의 몸을 고정 이끼 판이 실제로 가리는 것을 확인했다.
- 같은 화덕 위치의 normal 켬/끔, PointLight 켬/끔 PNG를 각각 저장해 껍질 홈·돌 요철과 부분 조명의 실제 변화가 보이는지 검토했다. 비교 상태는 실제 shader normalScale/PointLight intensity를 바꾸며 geometry·보행 위치는 유지한다.
- 390×620/DPR2 임베드에서 모든 조작 버튼·가로 넘침 없음, 전체 조망 후 화덕 좌표 클릭/시설 사용, 원본 보행 프레임의 실제 진행을 확인했다. 이는 실제 데스크톱 Chrome viewport 검증이며 휴대폰 기기 검증은 아니다.
- 정지 중 입력과 snapshot·누적 시간·렌더 횟수·Canvas PNG가 동일하다. 390→1100 폭 변경에서 snapshot을 유지하고 렌더 횟수 19→20으로 한 번 다시 그린 뒤 PNG/렌더를 고정했다. 화면 CSS 비율과 backing store 비율의 차이는 0.01 미만이다. 종료 이벤트 뒤 RAF·렌더가 멈추며 브라우저 예외/콘솔 오류는 0건이었다.
- 검토 PNG와 실제 상태 보고는 `/private/tmp/forest-*.png`, `/private/tmp/forest-verification.json`에 작성했다. 최종 라이브러리 preview는 통합 담당이 등록한다.

모든 새 소재와 미술 원본은 TypeScript 코드다. 승인된 인물 리소스는 읽기 링크로 재사용하며, 새 Git 제외 이미지 원본은 생성하지 않았다. 라이브러리 통합과 최종 preview 등록은 담당 세션이 수행한다.
