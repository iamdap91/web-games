# 짓는 골목 · 기능 전이

연결형 건축의 원래 항구·셀 크기·외벽·지붕·인접 아치 형태를 유지하고, 팝업북의 **조립이 끝나야 길을 열 수 있는 규칙**을 이식한 독립 시안이다. 종이 접힘 표현은 가져오지 않았다.

`ModularVisit`이 3초의 건축 시간을 소유한다. 기둥(0–1초) → 외벽(1–2초) → 지붕(2–3초)을 별도 동적 그룹으로 표시하고, 완료 시에만 `stage`를 바꾸어 원본 인접 표를 재구성한다. 건축 중에는 기존 충돌/클릭 경로를 유지한다. 지붕 완성 후 도장 아치가 열리며 두 번째 증축은 안마당을 완성한다. 새 건물이나 닫힌 아치가 발 위치에 생기면 안전한 입구로 이동한다.

- 클릭/터치: 실제 길을 찾아 걷기. WASD/방향키: 화면 기준 직접 걷기.
- `다음 증축` / R: 다음 3초 건축. 진행 중 중복 입력은 무시. 모두 완성 후 R은 비교 초기 상태.
- Space / 시설 사용: 가까운 화덕·도장·쉼터. M: 조망. Esc: 멈춤. 입구로: 복구 기록을 유지한 귀환.
- 좌표: 입구 `(0, 7.5)`, 도장 앞 `(0, 2.25)`, 아치 중심 `(0, 0)`, 안마당 `(0, -2.6)`, 화덕 `(-4.9, 4.45)`.

`window.villageStyleModularAssembly`은 ready/snapshot/project/screenPositions/paused/disposed/diagnostics를 읽기만 제공한다. `snapshot.assembly.phase`는 1~3, `diagnostics.routeOpen`은 실제 충돌 개방 상태다. embed=1에서도 조작 버튼을 남긴다. 승인된 아타호 원본 RGBA·프레임 비율·pivot·방향 프레임을 그대로 사용한다.

당시 검증: 담당 TypeScript 빌드와 ESLint, 로직 검사로 3단계 시간 진행·중복 요청·완료 전 충돌·완료 후 안마당 이동·닫힘 시 끼임 보정. Chrome embed 실제 실행에서 phase 2 진행 → 완료 → 클릭 안마당 `(0,-2.603)` 도착, Space 사용/멈춤/430px resize/두 번째 증축/pagehide 종료와 오류 0을 확인했다. 입구 순간 귀환은 한 바퀴 완주를 새로 만들지 않는다. 본게임 저장·경제와 연결하지 않는다.

## 라이브러리 통합 검토 · 2026-10-13

건축 중 단계 2의 통행 차단과 멈춤 보존, 완성 후 아치를 지나 안마당에 실제 클릭 보행으로 도착했다.

맵·마을에서 “기능 전이”로 검색한 9개 항목과 원래 맵·기능 출처 연결을 확인했다. 상세 안의 실제 키보드 보행 및 항목 전환 후 이전 뷰어의 disposed=true를 확인했다. 대표 PNG의 크기·SHA256은 resources/manifest.json에 기록한다. 좁은 화면 검증은 데스크톱 브라우저 뷰포트·DPR 에뮬레이션이다.
