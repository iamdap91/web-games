# 산들 두 갈래 길 · 기능 전이

A 맵: **산들 마을의 자연 지형형**. B 기능: **표현 비교장의 높은 길과 다리 아래 길 선택**.

## 제작 원리와 기존 시안의 차이

원본 언덕·하천·도장·나무를 보존하고 남쪽 다리를 높은 램프 다리로 바꿨다. 개울 방향의 낮은 판자길은 그 아래를 실제 통과한다. 다리 높이는 표시된 아타호의 머리까지 통과 여유가 생기도록 3.9로 두고, 기둥·램프·발 높이를 함께 계산한다. 경로 노드는 x·z·통행층을 함께 저장하므로 같은 교점에서 위아래가 섞이지 않는다. 높은 길은 빠른 횡단, 낮은 길은 느리지만 물빛 돌 발견이 있다. 층 전환은 실제 램프 끝과 낮은 길 양끝에서만 가능하다.

원본 폴더를 변경하지 않은 독립 시안이다. 환경은 Three.js 자체 제작이며 승인된 아타호 RGBA 프레임의 방향·비율·발 pivot을 사용한다. 기능의 이동·충돌·발견 상태는 Visit 객체가 소유하며 화면은 입력·렌더·수명만 연결한다.

## 조작과 확인 좌표

높은 다리 (8,3,high). 낮은 길 남쪽 입구 (8.6,6.8,low) → 다리 아래 (8.258,3,low) → 물빛 돌 (7.5,0,low). M 전체 조망에서 두 입구를 찾는다. 낮은 길에 들어선 뒤 클릭은 낮은 층을 우선한다.

WASD / 방향키 보행, 클릭·터치 장애물 우회 이동, Space / 사용 시설 반응, M 전체 조망, R 기존 도장 복구 비교, Esc 일시 정지. 정지 시 입력·생활 애니메이션이 멈추며 재개 후 이어진다. iframe embed 모드에서도 전체 조망·복구·멈춤·입구로·시설 사용 버튼을 유지한다. 소개만 줄이고 키 조작 설명과 상태를 표시하며, 944×538 및 390×620 크기 안에서 화면과 조작부를 배치한다.

## 입구 복귀와 완료 표시

입구로 버튼은 순간 이동이며 방문·발견·복구 기록을 보존한다. 이 시안에는 실제 귀환 보행의 완주·전체 완성 판정이 없다. 장소 방문이나 낮은 길 발견은 해당 위치에 걸어 도달한 별도의 기록이다.

## 검증

당시 로직 검사로 같은 xz 교점의 통행층 분리·램프와 낮은 입구 경유·실제 보행 도달·발견을 확인했다. Chrome 실제 실행으로 높은 다리 횡단, 낮은 입구 → 다리 아래 → 물빛 돌 클릭 이동, Space, 정지·재개, DPR 2와 세로 화면 리사이즈를 확인한다.

`window.villageStyleNaturalCrossing`는 읽기 전용 화면 조회용 진단이다. `ready`, `snapshot`, `project`, `screenPositions`, `paused`, `disposed`, `diagnostics`를 제공하며 게임 상태를 바꾸는 디버그 명령을 공개하지 않는다. 좌표는 canvas CSS 픽셀 기준이며 페이지의 canvas bounds를 더해 입력한다.

이 시안은 본게임 경제·저장·원정과 연결하지 않는다. 추가 이미지 생성이나 다운로드 없이 기존 승인 캐릭터와 직접 만든 환경을 사용한다.

## 라이브러리 통합 검토 · 2026-10-13

최종 높은 다리 3.9와 개울 아래 길 0.36에 각각 실제 클릭 보행으로 도착했다. 아래 길의 물빛 돌 발견과 Space 반응, 다리 아래의 머리 높이 여유를 확인했다.

맵·마을에서 “기능 전이”로 검색한 9개 항목과 원래 맵·기능 출처 연결을 확인했다. 상세 안의 실제 키보드 보행 및 항목 전환 후 이전 뷰어의 disposed=true를 확인했다. 대표 PNG의 크기·SHA256은 resources/manifest.json에 기록한다. 좁은 화면 검증은 데스크톱 브라우저 뷰포트·DPR 에뮬레이션이다.
