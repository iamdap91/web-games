# 개울 골목 · 2D 도트 생활마을

`local/village-style-pixel2d` / 마을 스타일 비교 ②.

배경·건물·기와·담·나무·생활 소품을 Canvas2D의 정수 픽셀 띠로 직접 그린 독립 보행 시안이다. 3D 모델이나 사각 상자를 픽셀화하지 않는다. 기존 승인된 `ai/tiger-hero`의 정면·옆면·뒷면 대기와 보행 프레임을 변경 없이 재사용한다. 캐릭터 그림을 제외한 미술은 외부 다운로드·AI 이미지 생성 없이 코드로 제작했다.

## 비교 장면

- 입구 `(0,11)` → 화덕 `(-5,3)` → 도장 `(1,-5)` → 개울 다리 → 뒷길 쉼터 `(10,-8)` → 위쪽 작은 다리 → 도장 뒤 골목. 같은 시설과 순환 동선을 2D 그림으로 해석한다.
- 공방 작업대의 망치·종이·물통, 벽의 쪽지, 기와 담, 빨래, 장독과 장작은 생활 흔적을 위한 그림 요소다. 시설 성장·저장·전투 규칙은 연결하지 않는다.
- 도장 복구는 판자와 오래된 기와를 문살·새 기와·홍등으로 바꾼다. 형태가 같아도 세부 그림으로 공간의 상태가 달라지는지 비교한다.
- 낮과 밤을 전환해 불빛·창문·홍등·개울 반딧불을 살핀다. 화덕 가까이에서 장작을 넣으면 8초간 불꽃·연기·바닥빛·공방 벽면의 명암이 함께 바뀐다.

## 표현과 책임

- `village.ts`: 발밑 반경·건물/나무/화덕/물 충돌, 다리 통과, 반 단위 길찾기, 방문, 복구, 화덕 시간을 소유한다. DOM·Canvas에 의존하지 않는다.
- `drawing.ts`: 제한된 색과 픽셀 면, 그림의 투영, 아타호 프레임, 조명을 그린다. 건물·나무·빨래·캐릭터는 발밑 z로 깊이를 정렬한다. 건물 뒤를 지나는 캐릭터가 실제로 가려진다.
- `index.ts`: 키보드·포인터·터치 버튼·화면 크기·루프를 연결한다. `pagehide`와 embedded `resource-scene-dispose`에서 RAF, 이벤트, ResizeObserver, 이미지 참조를 정리한다.
- 아타호는 약 43 논리 픽셀 높이로 표시한다. 그림을 다시 생성하지 않고 원본 프레임을 가까운 이웃 방식으로 축소한다. 카메라 이동은 정수 화면 좌표로 양자화한다.
- 조명은 바닥과 벽면을 구분한 색 합성이다. normal map·실제 입체 광원·그림자 계산을 구현한 것은 아니다. 순수 2D 그림의 제작 비용과 개성을 먼저 비교하기 위한 범위다.

## 조작

WASD/방향키와 화면 방향 버튼으로 걷는다. 캔버스를 누르면 물과 건물을 피하는 길을 찾아 걷는다. Space/근처 살펴보기는 화덕·도장·쉼터의 근접 상호작용이다. R/도장 복구, M/전체 조망, Esc/잠시 멈춤, 낮밤, 입구 복귀 버튼을 제공한다. `?embed=1`에서는 라이브러리 프레임에 맞춰 안내를 줄인다.

`window.villageStylePixel2d`는 읽기 전용 `ready`, `snapshot`, `paused`, `overview`, `disposed` getter를 제공한다. 보행·복구 상태를 바꾸는 진단 API는 제공하지 않는다.

## 레퍼런스와 적용

- [Eastward 공식 미디어](https://eastwardgame.com/media/): 세밀한 생활 흔적과 픽셀 그림에 조명을 결합하는 방향을 참고했다. 실제 Eastward 리소스·셰이더·맵을 사용하지 않는다.
- [Sea of Stars 공식 소개](https://seaofstarsgame.co/) 및 [공식 프레스킷](https://sabotagestudio.com/presskits/sea-of-stars/): 공간이 겹치는 배경 구성, 물과 건축의 연결, 낮밤의 분위기 변화가 참고 대상이다. 본 시안의 고정 2D 투영은 독자적으로 제작했다.
- [Unity 2D secondary textures 공식 문서](https://docs.unity.com/en-us/engine/7000.0/manual/unity2d/2d-urp/2d-index/secondary-textures): 색과 조명 정보를 분리한다는 연구 내용을 참고해 화덕의 바닥과 공방 벽면을 별도 영역으로 합성했다. 해당 normal/mask 파이프라인을 재현한 것은 아니다.
- [Three.js 텍스처 공식 설명](https://threejs.org/manual/pages/textures.html): 확대/축소 필터 개념을 참고했고, 이 Canvas2D 시안에서는 `imageSmoothingEnabled=false`와 `image-rendering:pixelated`를 사용한다.

## 검증

타입·린트·포맷 검사와 빌드를 수행한다. 건물/물/다리 판정·충돌·순환 길찾기·화덕 시간은 필요한 실제 조작으로 확인한다. 실제 설치된 Chrome을 Playwright로 실행해 키보드 이동, 포인터 길찾기, 화덕 반응 진행, 복구, 낮밤, 일시정지, 건물 가림, 쉼터 발견, 전체 조망, 390px 화면의 방향 버튼, embedded 종료 후 상태 고정을 확인한다. 390px은 CSS 뷰포트 검증이며 실제 휴대전화 검증은 아니다.

## 남은 비교 한계

이 시안은 손으로 정한 코드 픽셀 그림으로, 상용 게임처럼 전용 픽셀 아티스트가 각 장면을 그린 결과는 아니다. 상세 맵이 커질수록 개별 배경과 가림 영역 제작량이 늘어난다. 화면 축소 시 세부 소품이 묻히고, 기존 아타호의 밝은 팔레트는 배경보다 강하게 보인다. 시안에서 배경 색이나 캐릭터 원본을 임의로 교체하지 않고 비교 대상으로 남겼다.
