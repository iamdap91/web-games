# 저녁이 깃든 마당 · 디오라마·생활 조합

붓결이 머무는 마당의 회화 재질·고정 시점 색/깊이 합성에 시설 사용에 반응하는 생활을 더한 독립 시안이다. 큰 처마 도장, 굴뚝 공방, 낮은 천시장이라는 서로 다른 건축 실루엣을 유지한다. 새 효과를 넓게 채우는 대신 공방 뒤에 가려지던 작업대를 전면으로 옮기고 작업대와 수련 마당, 천시장 주변에 생활 흔적을 모았다.

## 직접 돌아보기

- 화면 클릭/터치 또는 WASD/방향키로 이동한다. 버튼이나 Space로 근처 시설을 사용한다.
- 공방 준비 → 도장 복구/수련 → 시장 천 펼치기는 실제 진행 상태로 연결된다. 먼저 다음 시설을 사용하면 선행 시설 안내가 나오고 방문은 기록되지 않는다. 작업 시간이 끝나도 준비/수련 완료는 보존된다.
- 공방 화덕 `(-4.5, 3.4)` 사용: 불씨·연기와 장인의 18초 붓질.
- 도장 `(-2.8, -4.9)` 사용: 도장 자동 복구, 훈련 북과 천막 활성화, 주민의 12초 발 디딤·수련.
- 담 뒤 쉼터 `(9, -6.7)` 발견 및 사용: 다리 또는 수로 끝 우회길 중 귀환 경로를 고른다.
- 천시장 `(2.4, 7.9)` 사용: 8초 동안 천 펼치기. 시장 뒤 빨래와 천막은 바람에 계속 흔들린다.
- 네 곳을 사용한 뒤 입구 `(-2, 10.5)`로 돌아오면 한 바퀴 완료가 기록된다.
- T/시간대 버튼: 낮과 저녁 비교. 저녁 공방 창빛과 복구 도장 등이 켜진다.
- R: 복구 전후 비교. M: 조망. L: 국소 빛. N: 재질 요철. Esc: 정지.
- 입구로 버튼은 이동 위치만 되돌리고 방문·복구·시간대·귀환 완료를 보존한다.

## 상태와 합성 책임

`LivingDioramaVisit`이 보행·경로·시설 타이머·복구·시간대·완주를 소유한다. `LivingDioramaScenery`는 정적 지형/시설과 바람 천막을 구성한다. `CourtyardLife`는 절차적으로 만든 32×48 직접 작성 픽셀 주민과 빨래·천·창빛의 합성 상태를 소유한다. `LivingDioramaScene`은 카메라·정적 색/깊이 캐시와 동적 깊이 합성을 관리한다. 화면 객체는 입력·정지·resize·수명만 연결한다.

배경 키는 복구·시간대·조망·빛·요철·backing-store 크기다. 주민 작업·시간·불씨·물·바람은 키에 넣지 않는다. 정지 후 resize는 동일 상태로 한 번 다시 합성하고 캐시를 갱신한다. `pagehide`와 `resource-scene-dispose`는 입력/RAF/관찰자/텍스처/깊이 타깃/지오메트리/WebGL을 정리한다. `embed=1`에도 버튼을 유지하고 시작 시 또는 버튼 동작 때 canvas를 강제로 focus하지 않는다.

`window.villageStyleLivingDiorama`는 읽기 전용 `ready`, `snapshot`, `paused`, `overview`, `disposed`, `project(point)`, `screenPositions`, `diagnostics`를 제공한다. `diagnostics`에는 `backgroundRenders`, `backgroundRevision`, `period`, `life`(작업/수련 프레임·천·빨래·창빛), 아타호 프레임/피벗과 캐시 크기가 들어 있다.

## 리소스와 범위

환경·주민·소품은 코드로 작성했다. 주민 정면 시안을 늘이거나 새 동작 프레임으로 해석하지 않는다. 아타호는 승인된 `ai/tiger-hero` 원본 RGBA 프레임과 방향 모션을 `TrailSprite`/`frame-pivot`으로 재사용하며, 수직판의 카메라 기울기 보정 외 이미지 비율과 픽셀을 바꾸지 않는다. 새 다운로드·유료 생성·패키지는 없다. 본게임 경제·전투·저장·진행과 연결하지 않는다.

## 검증

- `npm run check`, `npm run build`
- 당시 로직 검사: 계단·수로·담 충돌, 복구 안전 위치, 시설 간 실제 경로/귀환, 독립 작업 타이머, 시간대와 캐시키, delta 0 생활 정지 등 12개 검증.
- 브라우저 제공 도구는 이 서브에이전트에서 `Browser is not available: chrome` 및 빈 브라우저 목록을 반환했다. 실제 입력·화면·DPR/resize·embed·dispose 검증은 담당 세션의 최종 통합 검토에서 수행한다.

정적 광원은 낮/저녁 두 상태에서만 굽는다. 연속적인 해 이동과 주민 자유 보행/AI는 범위 밖이다. 바람 천막은 동적 깊이로 가림을 처리하며 움직임에 따른 정적 지형의 그림자는 매 프레임 다시 굽지 않는다.

## 통합 화면 검토 · 2026-10-13

통합 담당의 실제 내장 브라우저에서 화덕 작업→도장 복구/수련→쉼터→천시장→걸어서 입구 귀환의 4/4 방문을 확인했다. 작업 팔·빨래·천 펼치기 상태가 시간에 따라 바뀌며 보행과 시설 반응만으로 배경을 다시 굽지 않는다. 낮/저녁 전환에서 캐시 키와 창빛이 바뀌고 도장 창빛은 복구 후에 켜졌다. 정지 중 상태와 Canvas PNG가 같았으며 390×620 정지 resize에서 상태와 버튼을 보존했다. 종료 이벤트 뒤 disposed=true/ready=false였다. 좁은 화면 검사는 데스크톱 브라우저 뷰포트 검사이며 실제 휴대전화 검증은 아니다.

바탕은 낮은 붓질/요철 밀도로 줄이고 공방은 외쪽 낮은 단경사 지붕+굴뚝, 도장은 넓은 곡선 처마로 실루엣을 구분했다. 주민은 원본 RGBA를 가공하지 않은 아타호와 별도의 직접 작성 32×48 DataTexture(세이지/청회색 옷, 아래 발 기준, nearest, 접지 그림자)이며 새 유료 생성물은 없다.

## 확장 조합 통합 검토 · 2026-10-13

화덕 준비→도장 복구/수련→쉼터→천시장으로 실제 보행해 workshopReady/practiced/clothPrepared와 4/4 방문을 확인했다. 보행·시설 반응 중 배경 굽기는 2회로 유지됐고 저녁 전환에서 3회로 늘었다. 재방문 직후 returned=false이며 실제 입구 진입 뒤 true였다. 정지 snapshot/Canvas PNG 동일, 390×620 가로 넘침 없음과 종료 disposed=true를 확인했다. 실제 보행 진입으로 완주를 판정하는 회귀 사례를 포함한 당시 로직 검사 13개가 통과했다.

화면 크기 검사는 데스크톱 내장 브라우저 뷰포트 검사이며 실제 휴대전화 검증은 아니다. 대표 이미지는 통합 환경의 실제 렌더이며 PNG 크기·SHA256은 resources/manifest.json에 기록했다.
