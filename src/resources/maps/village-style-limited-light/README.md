# 두빛 마을 · 표면 조명 기능 전이

A `village-style-limited`의 384×240 정수 환경 래스터와 정확히 두 색 팔레트, 기존 골목·나무·냇물·건물 및 원본 컬러 아타호를 유지한다. B `village-style-lit2d`의 **높이장 법선 → Lambert 내적 조명**을 픽셀의 밝기 계산 앞에 이식했다.

## 새 동작

벽돌은 줄눈과 모서리 높이장, 기와는 둥근 단면의 높이장을 갖는다. 원본 lit2d의 `heightNormal`과 `surfaceDiffuse`로 표면 기울기 및 등불 방향의 내적을 구한다. 정면벽·옆벽·기와 경사면의 기본 법선도 다르다. 그 밝기를 **기존 4×4 Bayer**로 두 색 중 하나에만 기록한다. 부드러운 색 오버레이나 셋째 색 광원을 그리지 않는다.

L/등불 버튼은 도장 서쪽 `{10,16}`과 동쪽 `{21,16}` 사이로 등불을 옮긴다. 벽돌과 기와의 명암 방향을 비교할 수 있다. N/조명 버튼은 고정 명암과 표면 조명을 비교한다. 화덕 앞에서 Space를 누르면 장작불의 실제 추가 광원이 활성화된다. 입력·보행·클릭 우회·원본 컬러 아타호와 복구·쉼터 반응은 기존 방식이다.

디더 판정은 화면/카메라 위치가 아닌 원본 환경 픽셀 좌표를 사용한다. 이동·resize 때 무늬가 화면 기준으로 다시 생기지 않으며, 등불이 정지하면 조명 무늬도 정지한다.

## 조작·검증 좌표

WASD/방향키·터치패드·길 클릭으로 이동. Space 시설 사용, R 도장복구 비교, M 조망, Esc 정지, 입구로 위치복귀. embed=1에서도 등불/조명 버튼을 사용할 수 있다.

월드 `{x,z}`: 입구 `{23.5,27}`, 화덕 접근 `{14.5,23}`, 도장 접근 `{16,16.2}`, 쉼터 접근 `{35,7.3}`. 읽기 전용 `window.villageStyleLimitedLight.project(point)`, `screenPositions`, `ready/snapshot/paused/disposed/diagnostics`를 제공한다. 진단 `lighting/lampSide/surfaceLightCount/environmentColorCount/worldAnchoredDither/dpr`로 비교한다.

## 검증

당시 로직 검사로 법선과 광원 방향에 따른 밝기 차이, 두 색 양자화, 실제 화덕 접근·사용과 광원 수명/비교 상태를 확인했다. Chrome 실제등불 이동·조명비교·클릭 보행·Space 화덕광원·일시정지와 DPR2 모바일 resize·dispose를 확인했고 페이지 오류가 없었다. 타입 빌드·담당 ESLint를 통과했다. 본게임 저장·경제와 연결하지 않는다.

## 라이브러리 통합 검토 · 2026-10-13

등불 좌우와 조명 켜기/끄기의 실제 Canvas 이미지가 달라졌으며 환경 색 수는 2개를 유지했다. 멈춤 중 답사 상태가 고정됐다.

맵·마을에서 “기능 전이”로 검색한 9개 항목과 원래 맵·기능 출처 연결을 확인했다. 상세 안의 실제 키보드 보행 및 항목 전환 후 이전 뷰어의 disposed=true를 확인했다. 대표 PNG의 크기·SHA256은 resources/manifest.json에 기록한다. 좁은 화면 검증은 데스크톱 브라우저 뷰포트·DPR 에뮬레이션이다.
