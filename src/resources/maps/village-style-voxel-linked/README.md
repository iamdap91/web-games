# 이어진 네모골 · 기능 전이

복셀풍 네모골의 각진 기와·블록 메시·수로·단상·나무·아타호를 보존하고, 연결형 건축의 **이웃이 생기면 공유벽과 지붕을 다시 구성하는 기능**을 옮긴 독립 시안이다.

서쪽 공방에 같은 폭·깊이의 창고를 인접시킨다. 0 공방만 → 1 창고 복구(공유벽 닫힘) → 2 공방과 잇기(공유벽 관통 문·연속 처마·운반 발판). 단계 2에서 공방/창고의 실제 벽 메시가 통로 양옆으로 갈라지고, 충돌도 같은 통로 폭으로 바뀐다. 창고가 존재하는 것과 통행이 열린 것은 별도 단계다. `VoxelVisit`이 단계와 재설정시 끼임 보정을 소유하며 `voxelLinkTopology`를 표시·진단에서 사용한다. 기존 InstancedMesh 배칭과 재질을 유지한다.

- 클릭/터치: 실제 보행 경로. WASD/방향키: 화면 기준 직접 이동.
- R / 상단 버튼: 창고 복구 → 공방과 잇기 → 증축 전 비교. Space / 시설 사용: 가까운 화덕에서는 불을 지피며 다음 연결 단계도 진행한다.
- M: 전체 조망, Esc: 멈춤, 입구로: 단계 보존 귀환.
- 운반길 입구 `(-9, 6)`, 공유벽 문 `(-9, 1.075)`, 창고 뒤 출구 `(-9, -4)`. 문 중심에서 벽으로 ±0.4 이상 벗어나면 충돌한다.

`window.villageStyleVoxelLinked`의 ready/snapshot/project/screenPositions/paused/disposed/diagnostics는 읽기 전용이다. `snapshot.linkStage`와 `diagnostics.connection`이 현재 연결 결과를 보여준다. embed=1에서도 상단 조작과 시설 사용을 유지한다. 본게임 저장·경제와 연결하지 않는다.

검증: 빌드·담당 lint, 당시 로직 검사(단계별 공유벽 충돌·문 폭·관통 경로·실제 Visit 이동·초기화 끼임 보정), Chrome embed 실제 R 2회 후 `(-9,6)` → `(-9,-4)` 관통 클릭 도착, 직접키/Space/멈춤/430px resize/pagehide 종료와 오류 0 확인. 신규 창고와 기존 작업대가 겹치므로 작업대를 동쪽으로 1.7 옮기고 충돌을 동기화했다.

## 라이브러리 통합 검토 · 2026-10-13

창고만 복구한 단계와 공유문을 연 단계를 비교하고 운반길 입구에서 창고 뒤 출구까지 실제로 관통했다.

맵·마을에서 “기능 전이”로 검색한 9개 항목과 원래 맵·기능 출처 연결을 확인했다. 상세 안의 실제 키보드 보행 및 항목 전환 후 이전 뷰어의 disposed=true를 확인했다. 대표 PNG의 크기·SHA256은 resources/manifest.json에 기록한다. 좁은 화면 검증은 데스크톱 브라우저 뷰포트·DPR 에뮬레이션이다.
