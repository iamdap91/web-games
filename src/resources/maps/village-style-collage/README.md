# 뿌리 둥지 · 자연 콜라주

거대한 나무 뿌리 위에 아주 작은 버섯 마을을 구성한 독립 보행 시안이다. 각진 녹색 3D 마을이나 붓질 광장과 달리, 허공을 둘러싼 두 갈래 뿌리의 유기적 윤곽과 소재 밀도 차이를 중심으로 만든다.

## 참고와 실제 구현

- [Amanita Design · Samorost 3 공식 소개](https://amanita-design.net/games/samorost3.html)는 작은 인물이 낯선 자연 세계를 탐험하는 미술 방향의 참고다. 페이지가 내부 사진 합성 파이프라인을 명시하지 않아 그 제작법을 확인한 사실로 취급하지 않는다.
- 직접 구현한 것은 Canvas2D 콜라주다. 껍질 결/미세 입자, 이끼 반점, 버섯 반점/색, 얇은 종이 표지판의 소재판을 별도 Canvas에 작성한다. 큰 줄기와 뿌리, 버섯 지붕의 윤곽으로 소재판을 제한해 겹친다. 배경 줄기와 뿌리 몸체를 캐시하고 움직이는 시설과 인물을 그 위에 그린다.
- 껍질 홈은 그림으로 표현하며 실제 3D geometry, normal map, 사진 촬영 소재를 사용하지 않는다. 큰 뿌리 외곽과 두께는 직접 작성한 2D 윤곽이다. 다른 3D 시안에 접목할 때는 이 소재판을 표면 색으로 옮길 수 있으나 이 시안에서 검증한 범위는 2D 합성이다.
- 간판은 건물의 로컬 좌표에 고정된 그림이다. 늘어진 이끼는 발밑 z 순서로 그려 후면 길을 걷는 아타호 위에 실제로 겹친다. 이끼 뒤 쉼터를 찾으면 돌아가는 뿌리길의 푸른 포자가 켜진다.
- 아타호는 `ai/tiger-hero`의 승인된 로컬 대기/보행 4방향 원본 프레임을 읽는다. 원본 PNG·RGBA·가로세로 비율·pivot을 보존하며 보행 거리에 따라 프레임을 선택한다. 새 캐릭터 생성이나 외부 게임 미디어 복사는 없다.
- 실제 입력과 Canvas 그림을 설치된 Playwright/Chrome으로 검토했다. 새 패키지나 유료 서비스는 추가하지 않았다.

## 조작과 시설

WASD/방향키 또는 방향 버튼으로 이동한다. Canvas를 클릭하면 실제 뿌리 폭과 시설 충돌을 고려한 격자 경로로 걷는다. Canvas를 누르기 전에는 초기 포커스를 가져가지 않는다. Space/살펴보기는 근처 시설을 사용한다.

| 시설       | 접근 가능한 세계 좌표 `(x,z)` | 반응                                  |
| ---------- | ----------------------------- | ------------------------------------- |
| 입구       | `(-7.7, 2.5)`                 | 다시 돌아올 시작점                    |
| 씨앗 화덕  | `(-4.2, 2)`                   | 12초 불꽃/온기/증기, 주전자 진동      |
| 버섯 도장  | `(-0.8, -0.1)`                | 찢어진 지붕 잎 패치, 열린 문, 포자 등 |
| 호두 쉼터  | `(1.5, -3.4)`                 | 발견 기록과 후면 뿌리 포자 길         |
| 이끼 뒤 길 | `(-3, -3.7)`                  | 전경 이끼가 원본 아타호를 가리는 위치 |

도장 복구/R, 전체 조망/M, 잠시 멈춤/Esc, 입구로 버튼이 있다. 정지 중에는 시간과 움직임, 복구/상호작용/입구 복귀 입력도 멈춘다. 입구 복귀는 방문·발견·복구를 유지한다. 본게임 전투·경제·성장·저장은 연결하지 않는다.

## 수명과 통합 규격

`?embed=1`에서는 설명을 숨기고 모든 조작 버튼을 유지한다. `resource-scene-dispose` 또는 `pagehide`에서 RAF·입력 리스너·ResizeObserver·이미지와 소재 Canvas를 정리한다.

`window.villageStyleCollage`는 읽기 전용 `ready`, `snapshot`, `paused`, `overview`, `disposed`, `screenPositions`와 `project({x,z})`를 제공한다. `project`는 Canvas 내부 CSS 좌표를 반환하며 시점 변경 뒤 다음 렌더 프레임부터 반영된다. 상태를 바꾸는 외부 API는 없다. `screenPositions`는 시설 몸체 대신 실제 보행 접근점이며 중첩 좌표도 동결했다.

## 검증

- `npm run check`, `npm run build`, `node --test tests/village-style-collage.test.mjs`: 뿌리 순환/시설 반응, 허공과 몸체 충돌, 입구 복귀와 기록 소유권 3개 검사.
- 설치된 Playwright와 실제 Google Chrome, 1100×620/DPR2: 키보드 보행, 좌표 클릭으로 세 시설 순환, 12초 화덕 시간 감소, 도장 복구, 후면 쉼터 발견, 전경 이끼의 실제 가림, 전체/가까운 시점 좌표를 검토했다.
- 390×620/DPR2 임베드: 가로 넘침이 없고 시설/복구/시점/정지/입구 버튼이 보인다. 작은 화면 검증은 데스크톱 Chrome viewport 검증이며 실제 휴대폰 검증은 아니다.
- 정지 동안 시설 키/버튼/방향 입력을 눌러도 snapshot이 동일하며, 종료 이벤트 후 snapshot/RAF가 멈춘다. 검증 브라우저의 예외와 콘솔 오류는 0건이었다.

검토 PNG는 임시 검토 위치에 생성했고 라이브러리 통합 담당이 최종 라이브러리 캡처와 해시를 기록한다. 모든 미술 원본은 이 폴더의 TypeScript 코드이며 Git 제외 이미지 리소스를 새로 생성하지 않는다.
