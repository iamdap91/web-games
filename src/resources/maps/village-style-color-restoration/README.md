# 색과 길을 되찾는 마을 · 선화·복구·증축 조합

색돌이 마을의 굵은 선·흰 색면·색이 퍼지는 복구와 살아나는 골목의 실제 방·연결 통로 생성을 합쳤다. 처음에는 강 양쪽의 두 흰 구역과 끊긴 다리가 보인다. 서쪽 안료 공방을 가까이에서 복구해야 첫 다리가 생기고, 이를 실제로 건너 동쪽 찻집을 복구해야 새 다락방과 귀환 다리가 생긴다. 전역 색 버튼이나 원격 시설 복구는 없다.

## 실제 답사 루프

1. 입구에서 서쪽 안료 공방에 걸어가 Space/복구를 누른다. 2.4초 동안 공방에서 색이 퍼지고 다리 바닥이 차례로 그려진다. 서쪽 나무·집·화분에는 색이 돌아오지만 동쪽은 흰 선화로 남는다.
2. 연출 완료 후 첫 다리를 실제로 건너 동쪽 찻집에 간다. 다리 접합부는 물과 바닥을 같은 규칙으로 판정한다. 첫 다리 통과 전에는 두 번째 복구가 시작되지 않는다.
3. 찻집 가까이에서 Space/복구를 누른다. 두 번째 2.4초 연출 동안 동쪽에 색이 퍼지고 찻집 뒤로 이어지는 방의 밑그림과 남쪽 다리가 나타난다. 완료 전에는 새 방·통로·귀환 다리에 들어갈 수 없다.
4. 완료되면 기존 닫힌 찻집 본체가 문으로 이어지는 바닥과 실제 벽·가구로 바뀐다. 열린 앞문과 방 안 복도를 따라 새 다락방에 들어가 쉰다. 남쪽 다른 다리를 실제로 건너 입구에 돌아오면 한 바퀴 완료 반응이 나온다.
5. 입구 재방문 버튼은 위치·이동만 초기화한다. 구역 색·복구 진행·생성된 공간·시설 방문·다리 통과·귀환·누적 시간은 현재 페이지 메모리에 남는다. 새로고침은 새 답사다. 순간 입구 복귀만으로 실제 귀환이 완료되지는 않는다.

## 그림과 규칙의 경계

`layout.ts`의 `colorFloors` 사각형이 그려지는 바닥과 보행·클릭 경로의 공통 기준이다. 처음부터 있는 서쪽·동쪽 바닥과 복구 후 추가되는 첫 다리·방·귀환 다리를 구분한다. 인물 반지름의 네 방향 접점을 검사해 다리 연결 이음매를 막지 않고 강과 바깥 허공에는 들어가지 못한다. `roomWalls`와 `roomFurniture`는 그림과 충돌을 함께 제공한다. 기존 찻집의 닫힌 본체는 두 번째 복구 완료 후에만 실제 문/방 경계로 바뀐다.

그림은 새 `ColorDrawing`의 Canvas2D 큰 색면·굵은 선·비대칭 지붕·단순 생활 소품이다. 해당 구역의 원형 색 번짐이 바닥과 색면을 회복하고 다리의 생성 연출은 가로 방향으로 진행한다. 연결되지 않은 다리 중앙에는 강물이 그대로 보여 단절을 읽을 수 있다. 방은 앞을 자른 벽·지붕 띠·마루·침상·찻잔이 있는 단면으로 그려지며 실제로 안을 걸을 수 있다. 기존 시안을 iframe으로 감싸거나 전역 색만 바꾸지 않았다.

승인된 `ai/tiger-hero` 대기/보행 4방향 36개 원본 RGBA와 `AnimationPlayer`를 재사용한다. 인물은 선화 지역에서도 항상 원색이다. 원본 가로세로 비율과 아래 기준 pivot을 유지하며 인물에 grayscale·색 필터·재생성 아트를 적용하지 않는다. Canvas2D 도트 인물은 위치 깊이 정렬에 포함한다. 새 유료 생성·패키지·경제·전투·영구저장·본게임 연결을 추가하지 않았다.

## 책임과 수명

`ColorVisit`이 복구 시간·순서·이동·시설/공간 방문·통과 기록을 소유한다. `ColorDrawing`은 소재 없는 Canvas2D 장면과 원본 인물 재생/이미지를 소유한다. `ColorScreen`은 DOM·입력·포커스·정지·ResizeObserver와 RAF를 연결한다. 생성 완료는 Visit의 stage가 결정하며 그림은 해당 snapshot을 따른다.

초기화 시 포커스를 가져가지 않는다. Canvas를 직접 클릭하면 이동과 키보드 포커스를 얻는다. 버튼을 눌러도 Canvas로 포커스를 옮기지 않는다. Canvas/window blur와 pointercancel은 입력과 경로를 해제한다. 정지하면 복구 색·신규 공간 생성·인물 재생·누적 시간이 멈춘다. 정지 중 resize는 마지막 snapshot을 다시 그린 뒤 다시 고정된다. `?embed=1`에서도 조망·정지·재방문·시설 버튼을 유지한다.

`resource-scene-dispose`와 `pagehide`는 RAF·이벤트·ResizeObserver·이미지 참조를 정리한다. 로딩 도중 종료되어도 늦게 읽힌 이미지를 보관하지 않는다. 이 시안은 Canvas2D이며 WebGL/GPU 자원을 만들지 않는다.

## 조작과 검토 좌표

WASD/방향키 또는 바닥 클릭으로 걷고 Space/근처 살펴보기로 복구한다. M/전체 조망, Esc/멈춤, 입구 버튼/재방문을 제공한다. 작은 화면에서는 처음에 가까이 걷기, 넓은 화면에서는 전체 조망이다.

| 위치         | `(x,z)`    | 조건/반응                      |
| ------------ | ---------- | ------------------------------ |
| 입구         | `(-8,6)`   | 시작·실제 한 바퀴 귀환·재방문  |
| 안료 공방    | `(-7,0.5)` | 첫 구역 색과 다리 복구         |
| 첫 다리      | `(0,0)`    | 첫 복구 완료 후 실제 동쪽 통행 |
| 동쪽 찻집    | `(6,0)`    | 첫 다리 통과 후 두 번째 복구   |
| 열린 문/복도 | `(6,-1.4)` | 두 번째 복구 완료 후 통행      |
| 새 다락방    | `(6,-5.5)` | 실제 새 바닥 방문·쉼           |
| 귀환 다리    | `(0,5.3)`  | 새 방 방문 후 다른 길로 귀환   |

읽기 전용 `window.villageStyleColorRestoration`은 `ready`, `snapshot`, `paused`, `overview`, `disposed`, `project({x,z})`, `screenPositions`, `diagnostics`를 제공한다. project/screenPositions는 Canvas 내부 CSS 좌표다. snapshot은 stage(0/1/2), 구역별 regionProgress, restoring, 실제 다리 통과·새 방 방문·귀환·답사 횟수와 동결된 인물·방문 배열을 제공한다. diagnostics는 렌더/픽셀 크기·원본 인물 프레임·신규 바닥 개방·통과·방문을 제공한다. 외부 상태 변경 API는 없다.

## 검증과 한계

규칙 테스트 6개는 최초 접근/원격 복구 차단, 지역별 색 진행/연출 중 바닥 차단, 첫 다리 실제 통과 후 두 번째 복구, 방·문·복도 생성과 벽·가구 충돌, 다른 다리 귀환/재방문 보존, 정지/0초/잘못된 입력을 확인한다. `npm run check`, `npm run build`, `node --test tests/village-style-color-restoration.test.mjs`가 통과했다. 최종 실제 브라우저·임베드·입력·resize·dispose와 미술 검토는 통합 담당이 수행한다. 라이브러리 등록·preview 생성도 통합 담당의 범위다.

방의 높이와 지붕은 Canvas2D의 공간 그림이며 Three.js 고저차 보행은 아니다. 플레이어는 실제 바닥과 문을 따라 걷지만 단면 벽의 세밀한 앞뒤 가림은 향후 검토 대상이다. 순서와 구역 차이를 보여주는 작은 답사이며, 반복 플레이·경제 성장으로 확장하지 않았다.

## 확장 조합 통합 검토 · 2026-10-13

첫 복구 후 서쪽만 채색되고 동쪽은 흰 선화로 남았다. 첫 다리를 실제로 건너 찻집을 복구해 stage=2와 새 방/귀환 다리 생성, 실제 roomVisited를 확인했다. 귀환 다리를 건넌 뒤 재방문 버튼은 returned=false를 유지했으며 이후 실제 입구 진입은 true였다. 복구 중 정지 snapshot/Canvas PNG 동일, 390×620 가로 넘침 없음과 종료 disposed=true를 확인했다. 순간 복귀 회귀 테스트를 포함해 전용 7개가 통과했다.

화면 크기 검사는 데스크톱 내장 브라우저 뷰포트 검사이며 실제 휴대전화 검증은 아니다. 대표 이미지는 통합 환경의 실제 렌더이며 PNG 크기·SHA256은 resources/manifest.json에 기록했다.
