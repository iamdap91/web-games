# 두빛 마을 · 제한색 도트

잉크와 아이보리, 두 가지 빛으로 만든 생활 마을의 독립 답사 시안이다. 길을 걷고 빵 화덕에 장작을 넣고 빈 도장을 고친 뒤, 나무 뒤 찻잔 쉼터를 찾는다. 도장 옆 짧은 골목과 마을 서쪽 긴 산책길을 선택할 수 있다. 본게임의 경제·전투·성장·저장은 연결하지 않는다.

## 공식 참고에서 확인한 사실

- [Minit — Devolver Digital 공식 itch.io 페이지](https://devolverdigital.itch.io/minit)는 `1-bit` 태그와 강한 흑백 픽셀 실루엣·타일 화면을 공개한다. 해당 페이지와 공개된 화면을 직접 열어 확인했다.
- [Return of the Obra Dinn 공식 사이트](https://obradinn.com/)는 `with Minimal Colour`로 소개하며, [공식 공개 화면](https://obradinn.com/img/shots/People-10.png)에서 최소 색과 픽셀 디더로 면 명암을 표현하는 모습을 확인했다.
- 위 자료는 제한색과 디더의 시각 참고다. 원작 엔진·장면·사진 재현은 주장하지 않는다. 외부 게임의 이미지·모델·오디오를 프로젝트에 복사하지 않았다.

## 직접 구현한 것

- `palette.ts`: 환경 팔레트 `#17211e` / `#f0ebd1`과 4×4 Bayer 임계 16개. 밝기 0과 1은 온전한 단색, 중간값은 정수 픽셀의 색 점유율로 나타낸다.
- `drawing.ts`: 384×240 환경 버퍼의 각 정수 픽셀에 0 또는 1을 기록한다. 벡터 선화에 필터를 씌우지 않는다. 집·지붕·나무·화덕·빵·빨랫줄·울타리·찻잔을 직접 그린다. 큰 검은 실루엣, 무지 산책길, 풀밭·벽·지붕의 디더 밀도를 구별한다.
- 환경 디더 좌표는 마을 픽셀에 고정된다. 최종 확대는 DPR의 물리 픽셀 정수 배수, nearest-neighbor로 유지한다. 화면 이동·전체 조망 전환에서 픽셀 폭과 환경 팔레트를 유지한다.
- 기존 `ai/tiger-hero`의 대기·보행 36프레임을 사용한다. 원본 RGBA와 `width / height`, 가로 `pivot.x`, 발바닥 기준 `height - pivot.y`를 적용한다. 환경만 두 색으로 제한하며 아타호는 승인된 컬러를 유지한다. 캐릭터를 새로 생성하지 않았다.
- `village.ts`: 보행·충돌·클릭 경로·방문·14초 장작불·복구·입구 복귀를 소유한다. 집과 나무의 실제 충돌, 냇물과 다리의 통행을 반영한다. 환경과 아타호를 깊이 순으로 합성해 건물·나무 뒤를 걸으면 가려진다.
- `index.ts`: 입력과 UI, RAF, 수명주기를 소유한다. 초기 포커스를 가져오지 않는다. 정지하면 시간·보행·불·모션·화면을 함께 고정하고 게임 입력을 무시한다. `resource-scene-dispose` 및 `pagehide`에서 이벤트·ResizeObserver·RAF·이미지·픽셀 캐시를 정리한다. 2D Canvas이므로 GPU 재질·모델은 만들지 않는다.

## 조작과 답사

- 길 클릭·터치: 집·나무·냇물을 우회해 목적지로 걷는다.
- WASD / 방향키 / 화면 방향 버튼: 직접 보행. Space / 시설 버튼: 근처 화덕·도장·쉼터 사용.
- R / 도장 복구: 깨진 처마를 잇고 등불과 목인을 복구한다. 다시 누르면 복구 전을 비교한다.
- M / 전체 조망: 마을 조망과 가까운 보행을 전환한다. Esc / 잠시 멈춤: 시간·입력·표현 정지. 입구로: 위치와 보행 경로를 입구로 돌린다. 복구·방문·장작불·누적 시간·걸음은 유지한다.
- 화덕 접근점 `{ x: 14.5, z: 23 }`, 도장 `{ x: 16, z: 16.2 }`, 숨은 쉼터 `{ x: 35, z: 7.3 }`. 화덕은 불꽃·굴뚝 연기, 도장은 처마·등불·목인, 쉼터는 두 번째 찻잔으로 답사에 반응한다.
- `?embed=1`은 설명만 숨기고 복구·조망·정지·입구 복귀·시설 버튼과 이동 버튼을 유지한다.

## 읽기 전용 관찰 API

`window.villageStyleLimited`는 동결된 읽기 전용 관찰 객체다. `ready`, `snapshot`, `paused`, `overview`, `disposed`, `diagnostics`와 `project({x,z})`, `screenPositions`를 제공한다. `snapshot`에는 위치·방향·보행·시간·방문·근처 시설 ID·복구·불 시간·경로·반응 메시지가 있다. 시설의 `screenPositions`는 실제 통행 가능한 접근점의 Canvas CSS 좌표와 월드 좌표다. 외부에서 게임 상태를 직접 변경하는 함수는 제공하지 않는다.

`diagnostics`는 실제 환경 버퍼 색 수, 두 색의 값, 384×240 픽셀 크기, 디더 임계 수, CSS·backing 크기, DPR, 물리 픽셀 배수, 이미지·캐시·종료 상태를 제공한다.

## 검증

- `npm run check`, `npm run build`.
- 당시 로직 검사: 디더 임계 경계·타일 주기·밝기 점유율, 팔레트 2색, 집·물·다리·시설 접근점, 충돌 우회·세 시설 순환, 장작불 시간·복구·입구 복귀 후 답사 기록 유지·분리된 관찰 스냅샷.
- 설치된 실제 Google Chrome의 격리 프로필과 Playwright로 WASD·방향 입력·클릭 보행·화덕→도장→쉼터 사용을 실행했다. 초기 포커스는 BODY, 환경 진단의 실제 색 수는 2, 콘솔·페이지 오류는 0. 화덕 사용·도장 복구 뒤 실제 입구 복귀 버튼을 눌러 복구·방문·장작불·누적 시간·걸음이 유지되는 것도 확인했다.
- 정지 전후 관찰 스냅샷과 Canvas PNG SHA-256을 비교해 일치했다. 정지 중 이동·복구 입력도 상태를 바꾸지 않았다. 실제 불이 켜진 화덕에서도 불 시간·Canvas PNG가 고정되고, 재개하면 불 시간이 다시 줄었다.
- 390px / DPR2에서 이동 버튼과 모든 공통 버튼을 실행·확인하고, 1100×620 iframe에서도 embed 조작과 종료 이벤트를 확인했다. 이 검증은 실제 Chrome의 viewport/DPR 조건이며 실물 휴대폰 검증은 아니다.
- 답사·복구·가까운 픽셀 확대·모바일·iframe 화면을 직접 확인했다. DPR2 카메라 이동 전후와 조망 왕복 후 같은 월드의 4×4 디더 패치 픽셀을 비교해 일치했다. 근접 물리 픽셀 블록은 7px, iframe 조망 4px, 390px 조망 2px다. 종료 후 이미지 수·캐시 바이트·Canvas backing 크기가 모두 0이었다.
