# 동글 언덕 · 장난감 모형 마을

공식 자료에서 제시한 작은 디오라마 감각을 우리 프로젝트에서 시험하는 독립 시안이다. 고해상도 곡면과 큰 파스텔 색면, 둥근 광장, 부드러운 표면 명암으로 기존 저해상도 자연마을·각진 복셀풍 마을과 구별한다.

## 참고와 제작 출처

- [Nintendo 공식 아트 디렉터 설명](https://zelda.nintendo.com/links-awakening/blog/director-yoshiki-haruhana/): 약 10cm 크기의 인형이 있는 작은 디오라마와, 그 규모에 맞춰 세부 묘사를 절제한다는 제작 방향을 확인했다.
- 원문 서버 조회가 실패해 같은 내용을 게시한 [Nintendo UK 공식 기사](https://www.nintendo.com/en-gb/News/2019/October/Discover-what-graphic-refining-director-Yoshiki-Haruhana-aimed-for-with-the-visual-style-of-The-Legend-of-Zelda-Link-s-Awakening--1656228.html)를 확인했다. 참고 게임의 내부 셰이더나 제작 파이프라인을 재현했다는 의미는 아니다.
- 환경: Three.js 기본 geometry와 설치된 RoundedBoxGeometry를 조합한 자체 코드 제작. 외부 게임 이미지·모델 다운로드나 유료 생성은 없다. 둥근 돔과 타원 처마, 큰 색면, 우물 중심의 순환길은 이 시안의 설계 선택이다.
- 인물: 기존 승인 `ai/tiger-hero` 프레임만 사용한다. TrailSprite·SpriteTextures에서 원본 RGBA, 폭·높이·pivot을 재사용하며 픽셀 텍스처를 새로 만들지 않았다.

## 표현과 결합 방식

- 실제 CSS 크기 × DPR(최대2)로 antialias 렌더한다. 낮은 렌더 해상도나 표면 도트 후처리는 없다.
- RoundedBox·Sphere·Cylinder로 모형의 둥근 모서리와 돔 지붕을 만들고 StandardMaterial의 거칠기0.53과 약한 반사광을 사용한다. 햇빛·하늘빛과 PCF 필터 그림자를 공유한다.
- 간판은 건물 Group의 자식인 고정 Plane이다. 같은 StandardMaterial 조명을 받고 작은 앞쪽 간격과 polygonOffset으로 벽면 겹침을 줄인다.
- 아타호 판은 카메라 방위각만 따라 수직으로 세운다. 원본 비율을 세로 투영 보정하고 발 위치를 지형 높이에 맞춘다. 인물판을 카메라 pitch로 기울여 바닥·건물에 교차시키지 않는다.
- 렌더·보행·포인터 역투영이 같은 지형 높이를 사용한다. 발 그림자는 별도로 바닥에 접지한다. 코드로 만든 장식과 캐릭터의 재질 차이 자체도 이 혼합 시안의 관찰 대상이다.

## 동선과 조작

입구 → 왼쪽 공방의 화덕 → 광장 도장 → 오른쪽 언덕 쉼터 → 입구 순환. 우물과 중앙 건축을 좌우로 우회하는 선택이 있다. 클릭·터치는 0.4단위 보행 그리드에서 건물·우물·연못·벤치·목인을 우회한다. 실제 지형 고도는 언덕에서 약1.9이며 도장을 뒤로 돌아갈 수 있다.

- WASD·방향키: 화면 기준 보행. canvas를 누르면 입력 초점을 받는다.
- 클릭·터치: 길을 지정해 우회 이동. 건물·연못 내부 목적지는 거절한다.
- Space / 시설 사용: 가까운 화덕·도장·쉼터 반응. 화덕의 불빛·불꽃·주전자 김은12초 지속한다.
- R / 도장 복구: 바랜 지붕 ↔ 청록 지붕·화분·등·훈련 목인. 목인은 실제 충돌을 추가하며 그 자리에 있던 플레이어를 자유로운 앞쪽 공간으로 옮긴다.
- M / 전체 조망, Esc / 멈춤. 정지 중 시설·복구·귀환·카메라와 애니메이션 시간이 모두 고정된다.
- 입구로: 위치만 초기화하며 방문·복구 상태는 비교를 위해 보존한다.

`?embed=1`에서는 설명만 감추고 복구·조망·정지·귀환 버튼을 모두 유지한다. 초기 로딩에서 부모의 키보드 초점을 빼앗지 않는다. `resource-scene-dispose` 또는 pagehide 시 RAF, 이벤트, geometry, material, texture, shadow map와 WebGL context를 정리한다.

## 검증 기록

당시 로직 검사로 장애물·경계, 화면 좌표 방향과 대각선 속도/시간 상한, 전체 우회 순환 및 실제 높이 접지, 복구 목인 충돌·화덕 시간·방문 보존을 확인했다.

설치된 Chrome과 Playwright로 키·포인터 입력, 화덕·도장·언덕 순환과 귀환, 건물 뒤 가림, 복구 전후, 정지 상태 보존을 확인했다. 1100/390 CSS 폭 및 DPR2의 부모620px iframe에서 버튼·터치·초점 보존·가로 넘침·종료를 확인했다. 390 화면은 브라우저 에뮬레이션이며 실제 휴대폰 검증은 아니다.

본게임의 전투·경제·대화·저장에 연결하지 않는다. 이 시안은 표현·공간·조작 비교용이며 긴 플레이의 재미까지 검증한 결과로 취급하지 않는다. 이미지 썸네일과 라이브러리 등록은 담당 통합 세션이 최종 라이브러리 렌더를 캡처해 기록한다. 신규 Git 제외 리소스는 없으며 승인 아타호 디렉토리는 읽기 링크로만 사용한다.
