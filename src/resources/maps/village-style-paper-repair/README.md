# 종이골목 · 수선과 인쇄 기능 전이

A `village-style-paper`의 얇은 외벽, 접힌 지붕, 책장 바닥, 종이 나무와 승인된 아타호를 유지하고 B `village-style-color-restoration`의 **구역별 복구 → 실제 길 개방**을 종이 수선 규칙으로 옮긴 독립 시안이다. 단순 색 변경이나 iframe 조합이 아니다.

## 새 동작

- 시작 시 북쪽 종이는 잘려 있고 북쪽 건물의 인쇄 면은 빈 종이다. 화덕 앞 사용으로 2.4초 수선이 시작되어 종이 발판이 펼쳐진다.
- 완료 시점에 북쪽 건물의 원래 facade/roof/sign texture와 발판 인쇄가 돌아온다. 충돌과 클릭 경로는 완료까지 북쪽 진입을 막고, 이후 화덕 오른쪽 발판만 건널 수 있다.
- 도장 앞 사용으로 동쪽 뒷장이 2.4초 동안 수선된다. 완료되면 작은 집의 인쇄와 뒷장 바닥이 복원되고 도장 오른쪽 종이 발판이 통행을 연다.
- 쉼터 사용 후 동쪽 길로 입구에 실제 귀환하면 한 바퀴 완료가 기록된다. 입구로 버튼과 재방문은 수선·방문·발견 기록을 보존한다. 수선된 구역을 다시 사용해도 취소되지 않는다.
- 진행 상태는 이 시안의 메모리에만 있다. 본게임 경제·전투·저장과 연결하지 않는다.

## 조작·검증 좌표

WASD/방향키 또는 길 클릭으로 이동. Space/사용/R은 **근처** 화덕·도장의 수선과 사용. M 전체 조망, Esc 일시정지, 입구로 버튼은 위치만 되돌린다. embed=1에서도 이 버튼을 사용할 수 있다.

월드 `{x,z}`: 입구 `{0,9.45}`, 화덕 `{-4.2,3.5}`, 북쪽 발판 `{-2.7,0.4}`, 도장 `{1,-3.45}`, 동쪽 발판 `{4.2,-3.4}`, 쉼터 `{7.5,-6.4}`, 동쪽 귀환 `{9.3,6.6}`. 화면 좌표는 읽기 전용 `window.villageStylePaperRepair.project(point)`와 `screenPositions`로 얻는다.

`ready/snapshot/paused/disposed/diagnostics`는 읽기 전용 진단이다. `snapshot.repair`, `repairing`, `repairProgress`, `loopComplete`로 완료 전후를 판별한다. 일시정지는 수선·연기·입력 시간을 멈추고 종료는 이벤트·RAF·Three 자원을 해제한다.

## 책임·검증

`PaperVisit`은 수선 시간과 보행·발견·귀환을, `layout.ts`는 같은 수선 상태를 받은 충돌과 경로를, `PaperScene`은 종이 면의 펼침과 인쇄 texture 복원을 소유한다.

당시 로직 검사로 수선 완료 직전 통행 금지, 완료 후 발판 통행, 두 구역 순서, 쉼터와 실제 귀환·재방문 보존을 확인했다. Chrome 실제화덕→북쪽 수선→도장→동쪽 수선→쉼터→입구 보행 완주, 진행 중 일시정지, 모바일 resize와 dispose를 확인했고 페이지 오류가 없었다. 입구로 순간 복귀는 새 완주로 계산하지 않는다. 타입 빌드와 담당 경로 ESLint를 통과했다.

## 라이브러리 통합 검토 · 2026-10-13

화덕의 북쪽 수선과 도장의 동쪽 수선 완료 뒤 발판을 건너 쉼터를 방문하고 걸어서 입구로 귀환했다.

맵·마을에서 “기능 전이”로 검색한 9개 항목과 원래 맵·기능 출처 연결을 확인했다. 상세 안의 실제 키보드 보행 및 항목 전환 후 이전 뷰어의 disposed=true를 확인했다. 대표 PNG의 크기·SHA256은 resources/manifest.json에 기록한다. 좁은 화면 검증은 데스크톱 브라우저 뷰포트·DPR 에뮬레이션이다.
