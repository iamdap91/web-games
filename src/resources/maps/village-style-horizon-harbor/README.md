# 지평선 너머 나루 · 곡면·생활 조합

곡선 지평선의 실제 원통 정점 변형과 역투영, 산들 마을의 큰 자연 형태와 낮은 소품 밀도, 해풍나루의 준비 시설과 부두 생활을 결합한 독립 마을이다. 입구에서는 나루 끝이 지평선 뒤에 가려지고, 낮은 언덕을 넘어 걷는 동안 바다와 배가 나타난다. 여관·시장·보급소·창고는 별도 높이·처마·발코니·차양·큰 창고문으로 구분한다.

## 준비와 귀환

- 여관에서 차를 마시면 12초 동안 화덕 불과 김이 반응한다. 여관 사용은 답사 완료의 필수 조건이 아니다.
- 시장 도시락과 보급소 밧줄을 모두 챙겨야 창고에 짐을 전달할 수 있다.
- 짐 전달 후 가운데 나무 부두 끝에서 종을 울리면 종이 8초 동안 흔들리고 배의 돛이 1.6초에 걸쳐 내려와 펼쳐진다.
- 이후 육로 입구까지 실제 걸어 돌아와야 답사가 완료된다. `입구로`는 준비 기록과 돛 상태를 보존하지만 완료를 주지 않는다. 입구로 버튼을 썼으면 부두 종을 다시 울려 실제 귀환을 시작한다.
- 바다 위 이동은 금지한다. 폭 3.2의 부두는 해안에서 끊김 없이 연결되고 난간을 포함한 보행 폭은 2.7이다. 뱃길 끝은 바다를 바라보는 출구 표식이며 다른 원정 화면으로 전환하지 않는다.

시설 보행 좌표: 여관 `(-3,9.4)`, 시장 `(2.6,1.6)`, 보급소 `(-2.8,-2.8)`, 창고 `(2.8,-8.7)`, 부두 종 `(0,-20.5)`, 육로 입구 `(0,11)`. 모두 같은 보행 그래프에 연결된다.

## 지형·표시·입력

`curve.ts`의 반경 18 원통 변형을 지면·세분 지붕·간판·나무·부두·배 정점에 함께 적용한다. 자연 언덕 높이와 접지 높이는 `layout.ts`에서 정의하고 건물·부착물·캐릭터 발·그림자·클릭 바닥이 같은 높이를 참조한다. 논리 보행은 평면에서 건물·시장 좌판·나무·화덕·바다 경계를 검사한다. 그림자와 목적지 표식은 언덕 기울기에도 대응한다.

높이 있는 언덕 때문에 고정 반경 원통과 광선의 해석적 교점을 클릭 바닥으로 쓰지 않는다. 실제 굽힌 지면/부두 Mesh와 가장 가까운 raycast 교점을 먼저 구하고 `atan2`로 원래 보행 z를 되돌린다. 정점 변형 시 raycast bounding sphere도 다시 계산한다. 바다를 누르면 이동 목적지가 생기지 않는다. 건물 부근 클릭은 가까운 보행 격자로 우회한다.

카메라의 좌우 추적은 ±3.5, 곡면 중심 z는 -23~9로 제한한다. `전체 조망 · M`은 같은 곡면 위 길과 육로/뱃길 방향을 위에서 확인한다. `곡선 · C`는 같은 위치의 평면 비교다. Space/시설 버튼은 근처 시설, WASD/방향키와 길 누르기는 보행, Esc는 일시정지다. Canvas가 focus일 때만 키를 받고 초기 화면에서는 focus를 강제로 가져가지 않는다.

일시정지 때 이동·목적지·시설·종·돛·불·김·안내 시간 모두 멈춘다. 종료 시 등록 이벤트·RAF·geometry·material·texture·renderer를 정리한다. `?embed=1`에서 소개만 숨기고 조망·비교·정지·입구·시설 버튼을 유지한다.

## 리소스와 관측

환경 texture는 `art.ts` CanvasTexture, 건축과 배는 직접 만든 geometry이다. 외부 모델이나 유료 생성물을 쓰지 않았다. 기존 `ai/tiger-hero` 승인 stand/move 원본 RGBA·프레임 비율·pivot을 재사용한다. 새 주민 이미지는 추가하지 않았다.

읽기 전용 `window.villageStyleHorizonHarbor`: ready, snapshot, paused, overview, curved, disposed, screenPositions, project(point), diagnostics. snapshot의 prepared/cargoReady/restored는 각각 준비/짐 전달/출항 신호, sail은 펼침 0~1, bell/fire는 반응 잔여 초다. diagnostics는 radius/centerZ/elevation/camera, playerBentGround/actorFoot/playerProjectionInverse, sourceFrame 경로·크기·pivot, harborVisible/harborScreen, DPR backing-store 크기를 제공한다. project는 Canvas CSS 좌표다.

## 검증과 범위

당시 로직 검사 6개로 고저차 원통 역변환·언덕 높이/기울기·부두 접지·바다 경계와 경로·준비 순서와 실패·실제 귀환/입구 순간이동 구분·정지·반응 시간·입력 제한을 확인했다. 타입·린트·포맷 검사와 빌드를 수행한다. 실제 브라우저 입력·화면·좁은 화면 검증은 통합 담당이 별도로 확인해야 한다.

경제·전투·영구 저장·원정 전환을 연결하지 않은 독립 표현/답사 시안이다. 원통은 한 축으로 굽어 좌우 지평선은 평평하고 앞뒤 길만 굽는다. 별도 대규모 맵 성능 측정은 하지 않았다.

## 확장 조합 통합 검토 · 2026-10-13

초기 harborVisible=false에서 언덕을 따라 걷자 true가 되고 바다와 배가 드러났다. 여관·시장·보급소·창고·부두를 실제 사용해 prepared/cargoReady/restored와 돛 0.302→1의 진행을 확인했다. 부두 바깥 D 입력은 바다 경계에서 막혔다. 곡면/평면 전환과 키보드 육로 보행 후 실제 입구 진입으로 loopComplete=true를 확인했다. 정지 snapshot 고정과 독립 종료 ready=false/disposed=true를 확인했다. 390×620에서 캔버스 높이 448/영역 450(테두리 제외)이 맞고 가로 넘침이 없으며 실제 클릭으로 여관에 도착·사용했다. 좁은 안내는 방향만 남겨 인물을 가리지 않는다. 부두만 24분할하고 실제 곡면 메시의 54개 Raycaster 표본으로 접지 오차 <0.01/역투영 오차 <0.02를 검증했다. 당시 로직 검사 7개가 통과했다.

화면 크기 검사는 데스크톱 내장 브라우저 뷰포트 검사이며 실제 휴대전화 검증은 아니다. 대표 이미지는 통합 환경의 실제 렌더이며 PNG 크기·SHA256은 resources/manifest.json에 기록했다.
