현재 구현 분류는 작업 워크트리 `codex/combo-effect-selection`의 `f94d791` 기준이다. 루트 `AGENTS.md`, 루트 README의 동작 조합실 절, 조합실 README, `player.ts`, `drawing.ts`, `sandbag.ts`/`sandbag-drawing.ts`, `camera-effects.ts`/`camera-staging.ts`, `emphasis-effects.ts`, `impact-effects.ts`, `ground-effects.ts`, `speed-lines.ts`, `finisher-presentation.ts`/`finisher-signatures.ts`, `teleport-presentation.ts`, 기공·부위 효과·리소스 기록을 대조했다. 본게임 전체 기능이 아니라 **독립 조합실의 현재 구현**을 판정했다.

## 추가 후보 심층안 · 아직 구현하지 않은 4개

아래는 추가 비교안이며 구현·새 그림 제작 승인을 뜻하지 않는다. 다음 박자·수치는 프로젝트 비교를 위한 제안이며 원작의 검증된 수치를 옮긴 것이 아니다.

### 1. G05 · 기공 방출 순간의 방향 반동

- **목적과 적용:** 파동포를 쐈다는 행동과 멀리 있는 대상에 닿았다는 결과를 분리한다. 현재 카메라 반동은 명중 이후에만 발생하고 파동포의 반동 몸 그림은 이미 있으므로, 추가할 것은 첫 방출 시점의 작은 시점 반동이다. 권기탄·부유기탄까지 공통 적용하지 않고 먼저 파동포 하나로 비교한다.
- **박자:** 첫 방출에 빠른 반대 방향 이동, 이어서 짧은 복귀. 기존 빔 유지·4회 명중을 따라 여러 번 연속 흔들지 않는다. 실제 발사 시각과 명중 시각 사이가 짧으면 두 반동을 합산하기보다 하나를 우선한다. 화면을 연속 진동시키는 G04와도 다르다.
- **중복과 차이:** 이번 G60은 배경의 국소 굴절, G63은 빛의 반사다. 이 후보는 구도의 위치 변화이며 세 기법 모두 필요한지는 실제 비교로 결정해야 한다. 필살기 스냅 확대와 손 앞 빔 시작점이 화면 밖으로 밀리는 경우에는 적용하지 않는다.
- **필요 조건·자원:** 발사 시각과 진행 방향을 기공 데이터에서 읽고 같은 절대 동작 시각에서 같은 변위를 계산한다. 새 몸 그림·총기·렌즈·3D 카메라가 필요하지 않다. 시야 경계와 기존 카메라 선택 우선순위는 현재 합성 지점에서 조율해야 한다.
- **완료 판단:** 방출 직후의 힘은 커지되 손·기공 접속과 실제 명중점이 계속 읽혀야 한다. 1배 재생, 정지·탐색, 기존 반동 켬/끔과 크기2/3을 실제 비교하는 것이 필요하다. 이것은 이후 구현의 완료 기준이며 이번 보고서에서 검증한 결과가 아니다.
- **원자료 확인 범위:** [Roystan 원작성자 설명·코드](https://roystan.net/articles/camera-shake/)의 감쇠와 축별 강도 코드를 이번에 읽고, [61프레임 원본 GIF](https://roystan.net/media/tutorials/camera-shake/shake-trauma.gif)의 12개 시점(0·5·11·16·22·27·33·38·44·49·55·60)을 추출해 격자판의 흔들림→안정화를 봤다. Unity 프로젝트는 실행하지 않았다. 자료는 감쇠하는 흔들림의 근거이며 **파동포의 방향 킥을 원자료가 입증하는 것은 아니다**. 방향 킥은 현재 기공의 목적에서 도출한 가설이다.

### 2. G16 · 기술 뒤에 잠깐 남는 바닥 흔적

- **목적과 적용:** 입자와 빛이 사라진 뒤에도 방금 힘이 바닥을 통과했다는 짧은 기억을 남긴다. 지열파 한 기술을 우선 후보로 하고, 실제 마지막 분출의 바닥 위치에서 작은 자국이 회복 자세까지 남도록 한다. 빠른 잽·공중 킥·매 연타에는 적용하지 않는다.
- **박자:** 분출 중의 밝은 균열→광량 감소→좁은 어두운 자국 유지→동작 완료 전 정리. 원문의 permanence처럼 장기 저장되는 파괴 흔적과는 범위가 다른 조합실용 재해석이다. 지속 시간은 실제 회복 자세의 가독성을 보고 정하며 여기서 검증된 수치를 제시하지 않는다.
- **중복과 차이:** 현재 접지 먼지는 공기 중 입자, 지열파 균열은 능력의 활성 표현이다. 후보는 그것들이 끝난 뒤의 바닥 표면 변화다. 기존 국소 충격파나 이로전 경계빛처럼 밝은 신호를 늘리는 기능이 아니다.
- **필요 조건·자원:** 바닥 좌표와 발생 시각·종료 시각이 고정되어야 한다. 매번 입자를 누적 저장하지 않고 선택한 동작의 사건에서 직접 재구성해야 탐색·반복 결과가 같아진다. 기존 균열 형상 또는 절차적 작은 표면 무늬로 먼저 비교할 수 있다. 실제 자산이 필요하면 별도 승인·출처 기록이 필요하다.
- **부작용과 중단 조건:** 도장 바닥을 영구 파괴하는 설정으로 읽히거나 모든 반복에서 자국이 누적되면 현재 범위를 벗어난다. 자국이 다음 타격을 암시하거나 실제 공격 범위로 오인되면 더 짧고 옅게 줄이거나 제거한다.
- **원자료 확인 범위:** [Epic 공식 Decal Materials](https://dev.epicgames.com/documentation/en-us/unreal-engine/decal-materials-in-unreal-engine)에서 표면의 국소 손상·때 표현과 정적 비교 그림을 확인했다. 이 문서는 표면 수정의 구현 원리 근거이며 **자국의 시간적 유지·소멸을 움직이는 자료로 검증한 근거는 아니다**. Unreal 프로젝트·게임 실행·전투 후 잔해 플레이는 하지 않았다. 그 한계 때문에 현재는 구현 확정안이 아닌 낮은 확신의 후보로 둔다.

### 3. G48 · 기존 종결 글자의 붓 질감과 정착

- **목적과 적용:** 이미 있는 `天·終·虎·龍` 종결 글자의 의미를 더 늘리지 않고, 마지막 실제 명중 이후의 결산으로 읽히는 등장 박자를 만든다. 초구취호패타의 `虎` 한 글자로 먼저 비교하는 것이 수묵·캐릭터 정체성과 잘 맞는다. 현재 글자가 없다고 전제해 새 한자 기능을 추가하는 제안은 아니다.
- **박자:** 마지막 실제 접촉 이후 짧은 획 등장→한 번의 정착→기존 마무리 유지→가드 전에 정리. 도입 기술명·얼굴 컷인과 같은 시점에 겹치지 않고 연타 중간에는 띄우지 않는다. 글자를 계속 흔들거나 무조건 크게 키우지 않는다.
- **중복과 차이:** 지금은 `drawFinisherOverlay`에서 serif 텍스트를 낮은 알파로 나타낸다. 후보는 글자의 필압·거친 가장자리와 등장/정착의 질감이다. G36 얼굴 컷인은 발동 선언, 이 후보는 종결이다. 현재 endGlyph를 보존한다면 새 그림과 문구가 반드시 필요한 것은 아니지만 실제 붓 자형을 새로 만들 경우에는 자원 제작 범위를 확인해야 한다.
- **필요 조건·자원:** 현재 글자와 실제 마지막 접촉을 그대로 사용한다. 글리프 외곽의 마스크·질감을 추가해도 가독성과 원래 의미를 유지해야 한다. 출처 불명 붓 폰트를 다운로드하거나 다른 작품 글자 이미지를 잘라 쓰지 않는다. 새 자형·텍스처 생성은 이번 문서 작성의 승인 범위가 아니다.
- **부작용과 중단 조건:** 몸·착지·샌드백을 가리거나 특정 원작의 승리 화면을 과도하게 복제하면 제거한다. 종결 글자는 승리·KO 상태 판정을 뜻하지 않으며, 샌드백의 단순 마지막 명중을 사망으로 표시하지 않는다.
- **원자료 확인 범위:** [Capcom 공식 고우키 트레일러](https://www.youtube.com/watch?v=rvPjsz7itF8)의 공식 게시자·영상 존재를 이번 웹 검색으로 재확인했다. 순옥살 종결의 등과 `天` 유지에 대한 프레임 관찰은 2026-10-15 카메라 메모리의 기존 조사 기록을 참고했으며 이번 담당 세션에서 영상을 새로 재생하거나 프레임을 추출하지 못했다. 현재 조합실의 글자 구현은 코드로 직접 확인했다. **기존 관찰을 이번 영상 실행으로 기록하지 않으며**, 아티팩트의 G48 `검색 요약만` 배지도 그대로 남긴다.

### 4. G74 · 실행 버튼의 작은 눌림 피드백

- **목적과 적용:** 작업 도구에서 재생·처음부터·추천 조합 버튼을 눌렀다는 사실을 즉시 알려 준다. 기술의 힘·무게를 바꾸는 모션 효과와는 별개의 낮은 우선순위 UI 후보다.
- **박자:** 누르는 동안 소폭 축소, 놓으면 짧게 원래 크기로 복귀. 대기 상태에서 반복 맥동하거나 모든 체크박스·타임라인을 흔들지 않는다. disabled 버튼은 반응하지 않아야 한다.
- **중복과 차이:** 현재 활성색은 선택 상태를 나타낸다. 눌림은 클릭 중의 일시적 행동 피드백이므로 선택 상태와 함께 존재할 수 있지만 같은 의미로 사용하지 않는다.
- **필요 조건·자원:** CSS transform으로 레이아웃 공간은 보존하고 키보드 초점 표시를 유지한다. `prefers-reduced-motion`에서는 변형을 생략하고 색·테두리 피드백으로 충분하다. 추가 이미지·게임 상태·소리가 필요하지 않다.
- **부작용과 중단 조건:** 작은 버튼 글자가 흐려지거나 키보드 실행·버튼 포커스가 알아보기 어려워지면 크기 변화를 줄이거나 제거한다. 조합 버튼의 실제 적용 성공은 현재 안내 문구가 맡아야 하며 축소 애니메이션을 성공 판정으로 쓰지 않는다.
- **원자료 확인 범위:** [MDN `:active` 문서·예제 코드](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:active)와 [감소 모션 문서·예제 코드](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)를 읽었다. 서브세션 브라우저를 열 수 없어 해당 예제를 직접 클릭·재생하지 않았다. 문서와 코드 근거만 있는 후보이며 이번 UI 조작 검증 결과로 표현하지 않는다.
